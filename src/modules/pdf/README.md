# PDF и адресные свидетельства · шаг 4

Контракт для worker, сверки, остальных reader и веб-клиента. Все ID сущностей — UUID. Платных действий здесь нет.

## Worker · шаги 8 и 9

`createPdfService(db, { resolveOriginal, artifacts })` из `index.ts` возвращает инструменты. Для развёртывания с общей конфигурацией используется `createRuntimePdfService(db, config)`. Штатный сервис подключает адаптеры шага 11 и сохраняет представления в закрытом S3 префиксе `reader-evidence/<projectId>/`. Порт оригинала разрешает только версию назначенного проекта и возвращает метаданные, размер и поток проверяемых байтов. Хэш назначения обязателен.

- `map(source)` → `{source, readerVersion, units}`. `source`: `{projectId, documentId, versionId, sha256}`. Физические страницы нумеруются с 1. Каждая входит в карту, включая страницы с пустым нативным слоем.
- `page(source, read, page)`, `zoom(source, read, {page, box, dpi?})`, `native(source, read, {page, box?})`, `search(source, read, {page, box?, query})`, `ocr(source, read, {page, box?, dpi?})` → `{evidence, bytes}`. `read`: `{runId, branch: "A" | "B", operationKey}`. Устойчивый ключ назначает harness до вызова инструмента, повтор той же команды возвращает тот же ID и байты. Иное тело даёт конфликт. `evidence` хранит SHA-256 исходника, ID поступления и версии, адрес, профиль reader, преобразование в пиксели для изображений и SHA-256 представления. Передайте сохранённые `bytes` в шлюз и привяжите его квитанцию к `evidence.id`. Фиксацией фактической доставки управляет harness. Поиск фильтрует нативные строки указанной физической единицы по буквальному совпадению без учёта регистра и сохраняет фактически возвращённые строки. В обобщённом `open(source, read, request)` для этой операции передайте `representation: "native"` и `query`. Ноль совпадений оставляет обязанность осмотра открытой.
- `pin(source, read, input, tx?)` → сохранённая позиция. Вход `{evidenceId, scope, quote?, value?, unit?, normalizedValue?, box?, lineId?, limitation?, alternatives?}`, где значение и единица — исходные строки, `scope` — UUID назначенной области проекта. Передайте `pg.PoolClient` для записи в транзакции аренды и checkpoint. Текстовая цитата должна буквально входить в единственную возвращённую строку. При нескольких совпадениях укажите её `lineId`. `grounding: "text"` означает совпадение цитаты с выданной строкой. Применимость значения и точность OCR проверяются отдельно. Для пикселей положение сохраняется с `grounding: "visual"` до смысловой проверки. Отсутствующее значение или цитата требуют причины ограничения. Позиция ссылается только на выдачу той же версии, запуска и ветви.
- Явное утверждение о передаче закрепляется через тот же `pin`: `{ evidenceId, scope, quote, lineId?, box?, deliveryStatement: { status: "delivered" | "not_delivered", item, context?: { lineId, quote } } }`. Название предмета дословно входит в утверждение или текстовый контекст той же выдачи. Контекстный ID и цитата сверяются по сохранённым строкам. Для изображения передаётся рамка и полная цитата с предметом. Значение и единица у такого наблюдения отсутствуют. Обычное наблюдение сохраняет прежний ключ повторения.
- `listPositions(projectId, runId)` возвращает `{A: Observation[], B: Observation[]}` для сверки и выдачи инженеру. Во время первичного чтения harness выдаёт ветви только её контекст. Одна ветвь не может закрепить результат открытия другой. Позиции добавляются с новыми ключами, старые попытки остаются в истории.
- Арбитраж, аренды, назначение области, очередь, применение результата к оценке и квитанции доставки принадлежат внешним модулям.

## Координаты и HTTP · шаг 13

`Box = { x, y, width, height }`. Координаты — пункты (1/72 дюйма) от верхнего левого угла видимой области страницы **после** поворота. При рисовании рамки на сохранённой картинке по каждой оси применяется `pagePoint * pixelsPerPoint - pixelOrigin`. Для просмотра старой редакции исходник открывается по `source.documentId` и `source.versionId`.

| GET под /api/v1 | Ответ |
| --- | --- |
| `/documents/:documentId/versions/:versionId/reader/units` | Сохранённая карта физического оригинала, либо явная недоступность карты |
| `/documents/:documentId/versions/:versionId/reader/pages/:page` | PNG страницы для быстрого просмотра. `ETag` содержит SHA-256 исходной версии. |
| `/documents/:documentId/versions/:versionId/reader/units/:unitId` | Чтение части DWG текущей версии карты. Query `readerVersion`, `representation=native\|render`, один из `derivativeHandle` или `entityOrdinal` для отдельной сущности. Сохранение evidence выполняется отдельным путём |
| `/evidence/:id` | Версия, адрес, тип, преобразование, `contentUrl` и `originalHref`. При OCR также `inputImage.url` и `inputImage.transform` |
| `/evidence/:id/content` | Сохранённое представление. PNG для визуального чтения, JSON со строками и рамками для текстового |
| `/evidence/:id/ocr-input` | Точный PNG, переданный локальному OCR |
| `/observations/:id` | Позиция, область, исходная цитата, значение, единица, ветвь и ссылка `evidenceId` |

Переход к оригиналу берите из `originalHref`. Штатный intake отдаёт оригинал под `/api/documents/…/content`. Прямое открытие карты и представления проверяет полномочие на чтение всего проекта, поскольку источник может содержать несколько областей. Временный наблюдатель, назначенный только на область, получает метаданные наблюдения по назначенной области. При обновлении вкладки отображаются прежний ID версии и сохранённые байты.

Быстрый просмотр использует сохранённую карту, сверяет оригинал по SHA-256 и проверяет доступ повторно перед выдачей PNG. Рендер ограничен входом 32 МиБ, стороной 1600 пикселей и выходом 4 МиБ. При ограничении или занятости слота браузер открывает полный PDF через обычный маршрут оригинала. Готовые страницы хранятся в памяти вкладки до достижения лимита кэша или окончания текущего окна доступа.

Для автоматического сценария используйте разные элементы A/B на реальных страницах. Откройте обе позиции и их `/content`, сверьте SHA-256 перед и после перезапуска. Проверьте посторонний проект, подмену хэша и рамку за краем — результат закрепляться не должен. Остальные сценарии см. в проверках модуля.

## Подключение reader другого формата · шаг 11

Объявите `ReaderAdapter` с `format`, `version()`, `inspect(path)` и `read(path, request, unit)`. Путь передаёт сервис после проверки размера и SHA-256. `ReaderUnit` содержит стабильный ID физической единицы, её адресную метаинформацию и при наличии видимую геометрию. `ReaderAddress` несёт `unitId`, необязательную рамку и `locator` с адресными полями формата (например, лист и диапазон ячеек или пространство CAD и handle). Для текстового результата используйте `application/json` и `{ address, lines, limitations }`, где каждая строка несёт уникальный `id`, `text` и локатор или рамку при наличии. Для визуального результата возвращайте точные байты, тип изображения и преобразование, если применимо. Сохраняйте частичный или недоступный результат с его фактической точностью и кодом ограничения. Подключение через `createReaderService`, хранилище и проверка принадлежности общие. При создании собственного экземпляра передайте адаптеры третьим аргументом `createReaderService(db, dependencies, adapters)`. Эта проверка относится к `pdf`.

## Запуск и проверка

Worker использует Poppler (`pdfinfo`, `pdftotext`, `pdftoppm`) и Tesseract. Базовые языки OCR — `rus+eng`. Их можно задать через `FACADE_PDF_OCR_LANGUAGES`. Установочный профиль задаёт `FACADE_READER_PROFILE` и меняется при замене шрифтов, OCR-данных или конфигурации конвертации. В квитанции также остаются обнаруженные версии Poppler и Tesseract. Отсутствие OCR удерживает отдельное чтение, нативный слой и рендер доступны самостоятельно.

Начальный предел оригинала reader — 512 МиБ, задаётся `FACADE_READER_MAX_ORIGINAL_BYTES`. Распаковка и приёмка пользуются собственными лимитами. По умолчанию одна сторона изображения не превышает 4096 пикселей, площадь — 12 млн пикселей. Для слишком большой рамки инструмент возвращает ограничение и допускает меньшее адресное окно. Временная копия оригинала проверяется по размеру и SHA-256, применяется настроенный защитный остаток диска intake. Настройка пула исполнителей и изоляция ресурсов процессов относятся к профилю worker.

Автотест использует отдельную базу и закрытый бакет, выделенные стендом. После сборки и миграций:

```sh
db_env="$(infra/test-stand/stand new-db step4)" && source "$db_env"
npm run build:server
npm run migrate
node --test src/modules/pdf/backend.test.mjs
```

Тест проверяет координаты на исходных пикселях для четырёх поворотов. На стенде он получает версию штатным HTTP upload, выполняет экземпляр инструментов worker, слушает настоящий API, пересоздаёт API и инструменты и сверяет хэши результата и оригинала. Запуск без переменных стенда выполняет только проверку геометрии.
