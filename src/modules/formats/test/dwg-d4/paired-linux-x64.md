# Синтетическое сравнение архивного профиля и ODA · Linux x86-64

24.11.2026, база `bdcf3829af87c7cb87231416f193e827873c3c76`.
Входы — восемь записей [манифеста](corpus.json). До запуска и внутри
контейнера сверены SHA-256 обеих копий. Все выходы и контрольные файлы
сохранены под `.local/w34-pair-x64` отдельного worktree.

## Профиль

- Один контейнер Debian 12.15 Linux x86-64 на ARM64 OrbStack, с эмуляцией
  архитектуры. Локально установленный Debian OCI index
  `sha256:99c0b25c46d0214d5a2091092e7908907dcaecd6a962cde0ac700acee222b6f3`,
  платформенная идентичность
  `sha256:a3bba7dc7dbcc1f37c2856c51fc9a7fac96608f50cb87b1b4e4d8b8c85ae988e`.
  Сеть отключена, корень и входы read-only, лимиты 1 CPU, 512 МиБ,
  64 процесса, 96 МиБ tmpfs, 35 секунд на преобразование.
- Архивный конвертер 0.13.4 JLL amd64, архив SHA-256
  `521216527b73f953c26c6202e972676ad14c8ad812fc15f9c4af31ae2681f0b4`.
  ODA File Converter DEB 27.10.0.0, build 27.10.0.151591, SHA-256
  `c432002cc688f89ddf6a68ad68e877cd16da1d99ab8729386009c552cf73beb5`.
  Архив ODA получен с официального маршрута в частный каталог. Утилита
  запущена из read-only mount с Xvfb, без установки DEB и его скриптов.
  [Граница допуска](oda-terms.md)
- Оба выхода ASCII DXF R2000. Для ODA рекурсия и audit выключены.
  Доступные в DEB Qt/XCB и системные зависимости Debian использованы
  локально. Их список с SHA-256 сохранён в `desktop-runtime/packages.sha256`.
  Пакеты ОС подготовлены до отключения сети. В рабочем образе и Git ODA отсутствует.
- Протокол сохраняет exit, stdout, stderr, отдельные `.err` ODA, длительность
  и максимум RSS процесса. Для зачёта DXF проверены кодировка файла,
  `AC1015`, баланс секций, `ENTITIES` и финальный `EOF`. Штатный DWG-адаптер
  Facade AI получил сохранённые байты через локальный Unix-повтор. В отчёте
  сохранены листы, строки, ограничения и адреса производных. Токены временны
  и содержат SHA-256 пакетов, штатные ID образов конвертера не подменялись.

## XREF и диагностика

- При отсутствии, принятой, устаревшей и чужой соседней XREF архивный конвертер
  вернул один SHA-256 DXF
  `4cbf6505e76a66915f5dcbe503e7cef66367a7a681060984e5ec25a52973d65c`.
  Во всех выходах есть путь `xref-target.dwg`, собственные 70 mm хоста
  и `cad_external_reference`. Текст цели в хост не добавлен. ODA остановился
  на чтении хоста с ошибкой `AcDbDictionary` во всех четырёх вариантах.
  Поведение ODA при разрешении XREF в прочитанном хосте остаётся открытым.
- Отдельный повтор ODA `audit=1` на семи входах с DWG-сигнатурой.
  У всех exit 0 и прежняя ошибка в `.err`, DXF отсутствует. Заведомо
  неверная сигнатура исключена из этого повтора.
- Отдельный экспорт объектов в JSON для `recovery` дал 10 935 Б, SHA-256
  `dfa012b55a356b55959174ee46f5dd13e787962766e077f923c78093bb533957`.
  Адаптер сохранил 5 строк Model, включая обе опоры 13.25 и 28.5 mm,
  `cad_dwg_json_recovery` и частичную точность адреса.

## Положительный контроль ODA

Вне corpus.json использован вручную заданный ASCII [DXF R12](fixtures/oda-positive-r12.dxf)
с одним отрезком и одной подписью. В том же профиле ODA преобразовал
его в DWG R2000 SHA-256
`a540e1c248a97368c8b205d996768b8a94422f28cdbbb84d96c0e15026be5c44`
и затем обратно той же командой DWG→DXF R2000, audit=0. Оба exit 0,
stderr пусты, DXF SHA-256
`138ea78710951afe3440e751b108827bb7d49618498e5d4241297fddf524a22b`
структурно полный. Парсер Facade AI подтвердил Model, строку
`D4 POSITIVE | gap 37 mm` и концы отрезка (1, 2) и (11, 2).
Результат подтверждает работоспособность запуска, порядка аргументов
и чтения DWG R2000, записанного ODA.

Шесть однотипных ошибок ODA относятся к DWG из архивного Write API или
`dwgadd`: XREF создан через C API 0.14, кириллический контроль через
`dwgadd` 0.14, ведомость через `dwgadd` старой серии. Отдельные
`recovery` и `unreadable` специально проверяют обрыв и неверную сигнатуру.
Совпадение класса ошибок у файлов одного происхождения ограничивает
сравнение этим корпусом. Положительный круг ODA использует собственный
DWG-писатель и показывает другой исход. Проверенный обычный корпус,
серверное использование и квалификация D4/D6 остаются отдельными задачами.
