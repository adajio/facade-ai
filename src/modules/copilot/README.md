# Помощник инженера

Раздел «Помощник» проекта даёт два действия. Явный поиск показывает дословные совпадения, адреса и доступную границу индекса. «Спросить помощника» ставит вопрос инженера в существующую очередь шлюза. Участник области может искать текст действующих публикаций своей области и открывать выданный фрагмент. Изображения доступны в разделе «Фрагменты».

## Стыки и выполнение

- `GET /api/projects/:projectId/copilot/search?q=…&scopeId=…` возвращает `originals` для проектного инженера и `publications` для участника. `GET …/sources?id=…&scopeId=…` повторно проверяет право на представление. Для целой версии в остатке оценки используется `GET …/versions/:versionId`.
- `POST …/questions` принимает `{ question }` и штатный ключ идемпотентности. `GET …/questions/:id` выдаёт состояние собственного вопроса. Перед выдачей оснований проверяются права и закреплённые идентификаторы версий. Прежний текст с заменённой опорой остаётся в истории с датой среза. Пользователь может подставить его вопрос в форму для отдельной актуальной проверки.
- Адаптер использует `searchProjectMemory` и `readProjectMemory`. Ссылка фиксирует снимок, блок и строку, для OCR — артефакт Reader. Открытие таблицы возвращает ячейку и соседний контекст с исходными адресами. Происхождение и ограничения остаются при ссылке.
- Worker вызывает `processNextCopilot(runtime, signal)` также при выключенной модели. Для работающего маршрута используется `copilot_question` в текущем поколении шлюза с назначением `review`. Назначенный профиль и пределы шлюза задаёт оператор. Входы и права инженера проверяются при допуске эффекта и перед отправкой. Для синтетического OpenRouter применяется точный допуск проекта, области и хэшей оригиналов.
- Ходы поиска, открытия, дочитывания и ответа проходят через один Gateway с журналом и максимумом восемь ходов на вопрос. Для одного адресного OCR-перехода рабочее место сохраняется в курсоре, затем работу снова получает очередь. Для повторения сохраняются поколение, ключ эффекта и контекст запроса. Неизвестный исход удерживается до сверки шлюза.
- Помощник возвращает утверждения со ссылками на открытые места и остаток. Полномочия по оценке, инженерным решениям и письму выполняют действующие модули.

## Проверка

`npm run build` и `npm run typecheck`. Тест `node --test src/modules/copilot/copilot.integration.test.mjs` использует отдельные пустые синтетические БД `FACADE_COPILOT_TEST_DB` и `FACADE_COPILOT_TEST_JOURNAL` после применения миграций и DDL журнала. С `FACADE_COPILOT_BROWSER=1` запускается Chrome из `FACADE_CHROME_PATH` или системной папки macOS. Браузерная проверка оценок и полей каталога — `npm --prefix web run test -- copilot-assessment.spec.ts catalog-evidence-rule.spec.ts`.
