# Досылка и публикация событий · шаг 7

Общие функции принимают клиент текущей транзакции `pg.PoolClient`. Модуль не начинает и не фиксирует транзакцию вызывающей команды. Ошибки содержат `statusCode` и `code`.

| Экспорт | Вызывающая сторона |
| --- | --- |
| `lockScopes(tx, projectId, scopeIds?)` | Единый порядок — `lockIntakeProject`, затем `lockProjectScopes` из access, затем основания. Удержания, версии причин и поколения остаются в таблицах intake. |
| `assertScopesAvailable(tx, projectId, scopeIds)` | Вызывает общий замок и канонический `getIntakeGate` для каждой выбранной области. Возвращает состояния шлюзов. Действующая причина даёт `409 scope_held`. Далее вызывающий проверяет версии вопросов, каталога, текста и допустимость пункта. |
| `publishProjectEvent(tx, projectId, { type, payload })` | В конце транзакции изменения проекции, до commit. Payload состоит из ID и версий, доступных читателям проекта. Intake публикуется автоматически из собственного транзакционного журнала `intake_events`. |
| `readProjectionPosition(tx, projectId)` | Метаданные для составного экрана. Вызывающая сторона читает вместе с зависимыми списками в одной транзакции `inProjectionSnapshot`, которая использует `REPEATABLE READ READ ONLY`. |

Декларация/импорт, отмена и истечение проходят через intake. Шаг 7 вызывает `resolveIntakeHold` с ожидаемыми версией и поколением. Перед снятием причины шаг 7 обновляет затронутые основания через `applyAssessmentUpdate` в той же транзакции. Идентификация по ID области следует записям `project_scopes` из access.

Для актуальной выдачи проверка допуска и выбор неизменяемой редакции происходят под общим замком. После транзакции поток читает допущенную редакцию. При подготовке артефакта в фоне общая проверка повторяется перед фактической выдачей. История и фиксация ранее совершённой отправки используют права на конкретный снимок и явную прежнюю редакцию.

Публикация синхронна с записью. За общим замком проекта она продвигает версию проекции и курсор в той же транзакции. Откат не создаёт видимую позицию. Чтение событий повторяемо. При истёкшем или слишком новом курсоре клиент получает `snapshot_required`, сохраняет локальный ввод, читает новый снимок и начинает с его курсора.

## HTTP для рабочего места

Ниже пути относительно `/api` (совместимый префикс `/api/v1`). Для записи нужны проектные права инженера, `Idempotency-Key`, `Origin` и `X-CSRF-Token`. Ответы используют `Cache-Control: no-store`.

| Метод и путь | Вход и результат |
| --- | --- |
| `GET /projects/:projectId/snapshot?scopeId=…` | `{projectId, sliceId, cursor, projectionVersion, scopes, holds}`. Каждая область содержит `id, version, catalogVersionId, assessmentVersion, inputGeneration, holds`. `scopeId` нужен для допуска наблюдателя, назначенного только в область. В таком сеансе передавайте его и при чтении `/events`. |
| `GET /projects/:projectId/events?after=…&limit=100&scopeId=…` | `{events, cursor, head, hasMore}`. Курсор и версия проекции — десятичные строки. `cursor` указывает последний отданный элемент, `head` — позицию полного среза. Повтор возвращает тот же порядок до истечения. Для ограниченного чтения события превращаются в сигналы обновления без предметных данных. |
| `POST /projects/:projectId/supplements/links` | `{receiptId, letterId, sentId, itemId?}`. Без `itemId` связь относится ко всему отосланному снимку. Пункт проверяется в точном `sentId`. Отсутствующий или чужой объект даёт 404. |
| `GET /projects/:projectId/supplements/links?receiptId=…&letterId=…&after=…&limit=100` | `{sliceId, cursor, projectionVersion, items, nextCursor}`. Курсор следующей страницы привязан к фильтрам и срезу. При изменении среза сервер возвращает `snapshot_required`. |
| `PATCH /projects/:projectId/supplements/holds/:holdId` | `{generation, scopeIds}` и `If-Match` причины. Список областей непуст и может только уточнять применимость. Возвращает следующую версию причины. |
| `POST /projects/:projectId/supplements/holds/:holdId/resolve` | `{generation, reason, impacts: [{scopeId, assessmentVersion, questionIds}]}` и `If-Match`. `assessmentVersion` берётся из снимка области, для области без оценки передаётся `null`. Нужен результат проверки каждой классифицированной области. Затронутые вопросы возвращаются на внутреннюю проверку. Пустой `questionIds` фиксирует отсутствие влияния по области. |

Управляемый обработчик с уже проверенными опорами может вызвать `resolveSupplementImpact(tx, {projectId, holdId, generation, version, reason, impacts})` и передать `changes` в формате `applyAssessmentUpdate`. Порт проверяет источник причины и завершённость приёма, обновляет только установленные зависимости, сохраняет дельту и закрывает одну причину. Для ответов и адресных отказов используется `POST /letters/:letterId/responses` из [контракта писем](../letters/README.md).

В событии `supplement.impact_resolved` передаются `holdId` и `changes: [{scopeId, questionIds}]`. Подтверждённые записи intake, смены области и каталога, новые редакции и факты отправки/ответа письма публикует миграция `07_supplements_projection.sql`. Assessment и исследовательские вопросы добавляют события через `publishProjectEvent`. Все источники используют один курсор проекта. Восстановление после `409 snapshot_required` начинается со снимка. При смене сеанса или фильтра клиент отменяет предыдущий HTTP-запрос и отбрасывает его результат.
