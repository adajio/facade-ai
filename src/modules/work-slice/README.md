# Рабочий срез проекта

`GET /api/projects/:projectId/work-slices/current` возвращает `workSliceId`, координаты событий проекта, итоговые числа, допустимые фильтры, активное поступление и сохранённую версию оценки. Для старой области можно передать `scopeId`. Данные поступлений требуют доступа ко всему проекту. Полномочия проверяются при каждом открытии сохранённого адреса.

`GET /api/projects/:projectId/work-slices/:workSliceId/receipts` принимает `filter=all|open|processing`, `limit` от 1 до 100 (по умолчанию 50) и выданный сервером `cursor`. Итог `total` относится ко всему фильтру. Вместо курсора можно передать `receiptId`, чтобы открыть страницу выбранной строки. Ответ `selection=present|filtered|missing` поясняет результат выбора. При найденной строке `selectedReceipt` содержит её состояние в закреплённом срезе даже вне текущего фильтра.

В `open` входят незакреплённые описи и описи с ещё открытым составом. В `processing` входит поступление с ожидающей или выполняемой задачей подготовки карты, импорта, раскрытия контейнера или чтения. Завершённые и удержанные работы учитываются в состоянии чтения. Один оригинал с несколькими задачами учитывается в фильтре поступлений один раз на поступление.

Подтверждённые байты складываются из размеров принятых вхождений и подтверждённых частей незавершённых передач. Срез сохраняет порядок и строки. Он доступен до 30 минут в пределах 128 последних версий проекта. Код `409 snapshot_required` означает, что нужен актуальный срез с тем же фильтром и, если он задан, выбранным поступлением. Курсор одного фильтра и среза нельзя использовать в другом. На браузерном маршруте `workSlice` переносится вместе с `filter`, `document` и `row`.

`GET /api/projects/:projectId/work-slices/:workSliceId/receipts/:receiptId/inventory` читает подтверждённую закрытую опись в сохранённой редакции. При изменении редакции или открытом составе действует `409 inventory_snapshot_unavailable`. Актуальная рабочая опись остаётся доступной через `GET /api/receipts/:receiptId/inventory`.

Адресный тест `src/modules/work-slice/work-slice.test.mjs` использует изолированную мигрированную БД `test_work_slice_*` на loopback. Для запуска задаются `FACADE_WORK_SLICE_TEST_DB` и при необходимости `FACADE_WORK_SLICE_TEST_DIST`.
