## Сбой общей PostgreSQL

В 08:07:17 МСК серверный процесс PostgreSQL вышел с кодом 2. Тот же postmaster завершил другие сессии, выполнил WAL redo
и вновь принимал подключения в 08:08:59. Перерыв составил около 103 с. Контейнер оставался запущенным с нулём рестартов.

по имеющимся журналам не удалось. Установщик теперь использует `--no-recreate` для базы и `--no-deps` при переключении API и worker.

## Домены отказа журнала

`diskutil list physical` и `diskutil info` показывают два физических устройства. Внутренний SSD Mac — `disk0`, раздел Data
расположен на `disk0s2`. ADATA SE920 — `disk4`. Тома `ADATA SE920` и `cargo` оба принадлежат `disk4s2`.
Текущие экземпляры приложения и журнала хранят данные в одном `OrbStack/data.img.raw`.

| Отказ | Журнал в текущей VM | Возможный нативный PostgreSQL на `disk0` |
|---|---|---|
| Остановился отдельный процесс или контейнер приложения | Отдельный PostgreSQL журнала может продолжить работу | Продолжает работу при доступном macOS |
| Недоступна вся VM или потерян её файл-образ | Журнал недоступен, при потере файла данные журнала теряются вместе с ним | Зафиксированные намерения остаются доступны macOS. Нужен закрытый канал от восстановленного worker и сверка перед платным выходом |
| Физически потерян ADATA SE920 | Теряются рабочая VM и текущий журнал | Данные журнала на `disk0` сохраняются при исправном Mac. Восстановление приложения требует отдельной копии |
| Потеря всего Mac с подключённым SSD | Оба диска могут быть потеряны одновременно | Нужна независимая копия или журнал на другом узле |
