# Предварительный разбор пакета одним читателем

На локальном стенде producer выбирает запечатанные поступления, ожидает раскрытия архивов и сохранения подготовленного состава поступления. Для DWG проверяется сохранённая машиночитаемая производная. После подготовки служба читает адресные строки индекса доступных документов. Модель получает ограниченную выборку дословных строк, их номера и участки, имена файлов и сгруппированные причины ограничений. Сервис сохраняет полные адреса. В объём запроса входят метаданные и экранирование JSON. Отчёт показывает, сколько файлов и строк попало в запрос. Если доступных документов нет, служба пропускает вызов. Один вызов подписанного Codex с моделью gpt-6.1-terra возвращает позиции каталога, цитаты и черновик письма. Выборка ограничена; непроверенные позиции получают статус «Не оценено». Ответ доступен в «Комплектности» и «Письмах» проекта. Инженерную оценку и отправку письма ведут штатные модули приложения.

Служба запускается командой `node infra/local-terra/producer.mjs` после миграций и сборки сервера. Стенд передаёт переменные окружения:

- `DATABASE_URL` — рабочая база стенда.
- `FACADE_DATA_DIR` и `FACADE_CONVERTER_SOCKET` — каталог данных и сокет конвертера того же экземпляра, что у обработчика документов.
- `FACADE_SOURCE_ROOT` — каталог установленного приложения с пакетом pg.
- `FACADE_PRELIMINARY_BASE` — закрытый каталог журнала попыток, на постоянном диске.
- `FACADE_PRELIMINARY_PUBLISHER` — собранный `dist/src/modules/assessment/preliminary-package-review.js`.
- `FACADE_CODEX_ADAPTER` — локальный Python-адаптер Codex, принимающий совместимый с chat completions JSON через stdin и возвращающий вызов функции через stdout.

Перед вызовом служба проверяет наличие разбора для того же поступления, версии каталога, стадии и хэшей оригиналов. Для нового разбора непосредственно перед резервированием вызова служба сверяет идентификатор подготовленного состава и версию каталога. Полученный ответ сохраняется до публикации в БД. После обрыва с неизвестным исходом служба удерживает этот вход для сверки. Публикация доступна доверенному процессу. Проектный API чтения проверяет право доступа ко всему проекту.

Синтетические проверки границ, цитат и повторов запускаются командой `node --test test/local-terra-preliminary.test.mjs`.

После первичного разбора служба сопоставляет новые сохранённые наблюдения с требованиями и черновиком. Изменение найденной позиции требует источника, а правка существующего абзаца письма требует точного совпадения его текста. В интерфейсе можно сравнить каждую позицию и письмо с первоначальным обзором той же описи и каталога.
