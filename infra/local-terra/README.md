# Предварительный разбор пакета одним читателем

На локальном стенде producer выбирает запечатанные поступления, ожидает раскрытия архивов и сохранения подготовленного состава поступления. Для DWG проверяется сохранённая машиночитаемая производная. После подготовки служба читает адресные строки индекса доступных документов. Модель получает выборку дословных строк с участками и номерами для цитирования. Папки, имена файлов и причины ограничений передаются в компактных словарях. Сервис сохраняет полные адреса. Сначала отбираются строки, лексически связанные с каждым критерием каталога, затем источники чередуются по мере заполнения бюджета. Отчёт показывает число перечисленных файлов, файлов с переданными строками и оставшихся строк индекса. Если доступных документов нет, служба пропускает вызов. Один вызов подписанного Codex с моделью gpt-6.1-terra возвращает позиции каталога, цитаты и черновик письма. Выборка ограничена; непроверенные позиции получают статус «Не оценено». Ответ доступен в «Комплектности» и «Письмах» проекта. Инженерную оценку и отправку письма ведут штатные модули приложения.

Служба запускается командой `node infra/local-terra/producer.mjs` после миграций и сборки сервера. Стенд передаёт переменные окружения:

- `DATABASE_URL` — рабочая база стенда.
- `FACADE_DATA_DIR` и `FACADE_CONVERTER_SOCKET` — каталог данных и сокет конвертера того же экземпляра, что у обработчика документов.
- `FACADE_SOURCE_ROOT` — каталог установленного приложения с пакетом pg.
- `FACADE_PRELIMINARY_BASE` — закрытый каталог журнала попыток, на постоянном диске.
- `FACADE_PRELIMINARY_PUBLISHER` — собранный `dist/src/modules/assessment/preliminary-package-review.js`.
- `FACADE_CODEX_ADAPTER` — локальный Python-адаптер Codex, принимающий совместимый с chat completions JSON через stdin и возвращающий вызов функции через stdout.

Перед вызовом служба проверяет наличие разбора для того же поступления, версии каталога, стадии и хэшей оригиналов. Для нового разбора непосредственно перед резервированием вызова служба сверяет идентификатор подготовленного состава и версию каталога. Полученный ответ сохраняется до публикации в БД. После обрыва с неизвестным исходом служба удерживает этот вход для сверки. Публикация доступна доверенному процессу. Проектный API чтения проверяет право доступа ко всему проекту.

## Бюджет и журнал

Первичный обзор и ревизия допускают до **60 000 байт** и **65 536 оценочных входных токенов**. Учитывается большее из полных UTF-8 JSON тела stdin адаптера и prompt для CLI. Включены системная инструкция, каталог, исходные строки, метаданные, схема функции и экранирование. Для байтового BPE число токенов переданного текста не превышает его длину в UTF-8. Расчёт добавляет 8 192 токена резерва профиля под обрамление Codex и фиксированные инструкции. В данном профиле отключены инструменты CLI и документы проекта, используется отдельный файл инструкций и короткая схема ответа. Приватный токенизатор Terra и полный HTTP-запрос провайдера недоступны. Предел токенов применяется к консервативной оценке, а фактический расход сохраняется отдельно из ответа адаптера.

При переполнении фиксированной части запроса вызов отклоняется до записи оплачиваемой попытки. В ревизии размер сокращается отбором наблюдений с сохранением адресов, а остаток может попасть в следующий штатный пакет. Журнал попытки связывает расчёт, фактические токены, охват, остаток, длительность и идентификатор опубликованного разбора. Время до первого результата считается от создания поступления до первой публикации. Известный отказ транспорта хранится отдельно от неизвестного исхода. Возобновление использует сохранённый ответ или точную публикацию без повторной отправки.

Сохранённый успешный запуск 26.11.2026 содержал 150 214 байт CLI prompt и 64 374 входных / 1 534 выходных токена. При офлайн-подготовке большой исторической выборки новый запрос занял 57 367 байт stdin и 57 332 байта CLI prompt при оценке 65 524 токена. Все 306 файлов перечислены, 287 имеют переданные строки, 337 строк выбраны из 5 000 доступных в сохранённой выборке. Сверка выполнена на фактической функции сериализации адаптера без запуска Codex.

Синтетические проверки границ, цитат и повторов запускаются командой `node --test test/local-terra-preliminary.test.mjs test/preliminary-revision-recovery.test.mjs`.

После первичного разбора служба сопоставляет новые сохранённые наблюдения с требованиями и черновиком. Изменение найденной позиции требует источника, а правка существующего абзаца письма требует точного совпадения его текста. В интерфейсе можно сравнить каждую позицию и письмо с первоначальным обзором той же описи и каталога.

## Журнал для внутреннего тестирования

Миграция 42 ведёт хронологию по проекту и поступлению в PostgreSQL. Для каждого события сохраняются время, стадия, исход, код ограничения, идентификаторы попытки и источника. При наличии сохранённых данных видны объём, токены и время до первой матрицы с письмом. Первые записи для ранее загруженных пакетов помечены по происхождению. Для состояний без исходной даты перехода указывается момент снятия состояния.

В профиле локальной подписки после создания таблицы local_terra_calls обработчиком выполните infra/local-terra/register-activity.sql через psql с ON_ERROR_STOP. Команда повторяема. Экспорт запускается как отдельный процесс с DATABASE_URL и FACADE_ACTIVITY_DIR командой `node infra/local-terra/export-activity.mjs`. Он каждые 15 секунд атомарно обновляет закрытые дневные файлы Markdown и JSONL, группируя их по локальной дате Москвы и UUID проекта. Ключ --once даёт одноразовый экспорт. Каталог экспорта должен находиться вне web-root. После перезапуска экспорт восстанавливается из БД. Неизвестный исход не является основанием повторить модельный вызов.

В локальной установке каталог model содержит call.py, instructions.txt, закрытый tmp и пустой рабочий каталог empty. Поддерживаемая копия адаптера лежит в infra/local-terra/model. Адаптер явно запускает gpt-6.1-terra с effort high. Для изолированной сравнительной пробы можно передать FACADE_TERRA_REASONING_EFFORT=medium. Фактический выбор и измеренный расход пишутся в локальный журнал адаптера; раньше сохранённые ответы переиспользуются со своей историей. Для OCI reader сборки Tesseract и языковые пакеты входят в образ reader. На нативном стенде обработчик находит их по PATH.
