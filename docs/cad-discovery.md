# Навигация по записям DWG

Навигатор помогает выбрать исходную запись в локальном экспорте LibreDWG. Каталог показывает пространства, слои, физические типы и форму записи одинаковым способом для каждого чертежа. Исполнитель сам выбирает область, объект и глубину чтения.

## Что доступно

- По каждому DWG в общую карту входят модель, пространства листов и сводные счётчики. Отдельно доступны определения блоков, служебные записи и сущности с неустановленной областью хранения. Полный список и численность открываются на уровне чертежа.
- Внутри области доступны слои, типы объектов, текстовые, многострочные и структурные записи, табличные сущности, вспомогательные записи таблиц, признаки полей и геометрические сущности. Слои и типы отображаются с численностью. Категории по форме могут пересекаться.
- Многострочность определяется по явным разрывам строки. Структура текста определяется по признакам табуляции, колонок или ячеек в разборе. Группы по числу строк и символов помогают выборочно открывать объёмные записи. Число символов относится к исходным текстовым полям и включает управляющую разметку.
- Сущности `TABLE` и `ACAD_TABLE` имеют собственную группу. Определения стилей и вспомогательная структура хранятся в смежной группе. Таблица, разложенная на надписи и линии, доступна по типам её составляющих.
- Карточка поля показывает конкретный наблюдённый признак. Это может быть тип записи, ключ, словарь `ACAD_FIELD` или лексическая разметка `%<…>%`. Такие признаки не рассчитывают поля и не подтверждают видимое значение.
- Карточки показывают исходный handle, тип, слой, область хранения и координаты из исходной записи там, где они доступны. Для размещения блока карточка ссылается на определение. Заголовок выдачи показывает размер выборки, текущий диапазон и число единиц вне ответа.

## Как открыть запись

`CadIndex.from_directory(path, mapping)` читает JSON LibreDWG из указанного локального каталога. Входной словарь отображает нейтральные идентификаторы документов `dN` на базовые имена файлов. Клиент может передать имя без расширения либо с расширением `.dwg` или `.json`.

1. `overview()` даёт общую карту DWG. `browse("cad")` открывает постраничный список чертежей. `browse("cad/d1")` открывает пространства и сводные ссылки по форме. Здесь `d1` служит примером идентификатора.
2. Маршрут `cad/d1/all/forms` перечисляет физические признаки. В любой области можно открыть `layers`, `types`, `forms`, `paragraphs` или `length`. Группы можно последовательно пересекать, например `cad/d1/all/forms/multiline/types/MTEXT`.
3. К маршруту любой области или выборки можно добавить `/order/paragraphs` или `/order/length`. Такой просмотр упорядочивает карточки по убыванию выбранной величины, затем по исходному handle. Карточки отдельного пространства и общего списка идут по handle. В сводной области определений блоков карточки сгруппированы по определениям. Ответ указывает следующий `start`.
4. `browse("d1:hA")` открывает карточку по исходному handle. `source_ref("d1:hA")` проверяет адрес и возвращает его в канонической форме для `read` исходной записи чтением DWG. Полные значения и координаты сверяются с этим исходным чтением.

Каталог не хранит посещения между вызовами. При независимых слепых прогонах история просмотренных диапазонов относится к каждой ветви отдельно.

## Границы покрытия

Численность отражает записи, доступные в локальном экспорте LibreDWG. Нулевой счётчик фиксирует результат распознавания записей данного типа или формы. Он сам по себе не позволяет установить отсутствие на листе. В частности, координаты из определения блока относятся к его собственной системе, а экземпляры размещения не размножают счётчики определения. Порядок отрисовки, вложенные преобразования, видимость слоёв, результат вычисления поля и графическое покрытие устанавливаются отдельно. Табличная структура из отдельных графических объектов требует проверки их взаимного положения.

Прежний текстовый поиск обходил пространственные `cad_group` и `cad_view`, при этом искал в агрегатах `cad_index`. Агрегаты включали строки из поддерживаемых текстовых полей и размерных записей. В процессе нормализации команда `\P` превращалась в пробел, а группировка по слоям, физической форме и месту хранения отсутствовала в выдаче поиска. Поэтому прежний поиск мог вернуть совпадающую строку, но не давал модели общего пути к многострочным или структурным объектам до подбора слов запроса.

## Проверка

Команда для запуска из корня проекта.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s experiments/package_review -p 'test_cad_index.py' -v
```

[Синтетическая проверка](../experiments/package_review/test_cad_index.py) охватывает два чертежа, пространство модели и лист, блок и атрибут его размещения, слои, свободную геометрию, многострочный текст, табличную сущность и стиль, признаки поля в тексте и вспомогательных записях, неустановленного владельца, адреса и пагинацию.
