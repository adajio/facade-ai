# Инженерный вопрос, доказательства и досылка

Редакция 0.16, 22 ноября 2026 года. Инженер работает с вопросом по выбранной стадии и области. У вопроса есть стабильный идентификатор, предмет, область, обязательные роли источников, допустимые названия предмета и, для внешней переписки, утверждённая формулировка запроса. Профиль задают один раз на проект. Загрузка принимает обычные оригиналы и их опись. Вопрос существует и при нуле найденных строк.

В редакции 0.17 в карточке доступны обе позиции с адресами исходных строк, в том числе при удержанном решении. Порядок передачи спора и правила письма приведены в [профиле двух автономных читателей](conditional-review.md).

## От обычной загрузки до решения

1. Проверить байты оригиналов и связать классификацию документа с его хэшем. Проверенная область и роль могут поступить из reader при загрузке нового, ранее неизвестного документа. Второй источник классификации — закреплённая запись профиля. Расхождение этих источников, неизвестная принадлежность или подмена файла оставляют открытыми зависимые выводы. Имя файла само по себе недостаточно.
2. Два первичных читателя сохраняют каждое адресное наблюдение с моделью, квитанцией, поступлением, оригиналом, единицей и номерами строк. Harness прикладывает сами строки из reader. Первичный читатель может номинировать один или несколько вопросов по содержанию фрагмента. Номинация не подтверждает ответ. Прежние правила широкого чтения и общего денежного допуска действуют также для досылки. [Правила охвата](reading-coverage.md)
3. Сопоставить вопрос с адресами всех применимых поступлений проекта. Встроенный поиск проверяет предметный словарь и передаёт на смысловую оценку также фрагменты источников нужной роли и области, даже если обе модели использовали совершенно другие обозначения. Номинации читателей и дополнительный локальный смысловой индекс могут предложить фрагмент иной роли. Индекс возвращает только идентификатор существующего факта разрешённой области и причину выбора. При ошибке индекса конкретный вопрос остаётся на сверке. В карточке видна причина включения каждого кандидата. При обычной загрузке с инженерным профилем одноимённые позиции разных фасадов не инициируют самостоятельное платное сравнение.
4. Передать кандидатные строки проверяющим. Смысловую связь, применимость к стадии, объект, единицы, действующие редакции и содержание оценивают по оригиналу. Каждая из двух оценок содержит решение, обоснование и ссылки на собственные чтения. Для принятия результата обе должны сойтись на статусе и физических основаниях. Полный набор кандидатов остаётся доступен рядом с отдельно выделенными принятыми опорами. Один принятый источник может отвечать сразу на несколько вопросов.
5. Показать инженеру машинный ответ по каждому вопросу, причины удержания, адреса, цитаты и обе оценки. Инженер принимает решение по текущему срезу и выбирает внешние пункты. Сохранить автора, срез, выбранные пункты и текст. Пустой выбор даёт решение без письма. Отправка остаётся отдельным действием.

| Машинный исход | Минимальное основание в исполняемом профиле | Переписка |
|---|---|---|
| Покрыто | Две оценки подтверждают содержательные адресные чтения по всем обязательным ролям источников | Внешнего пункта нет |
| Нехватка | Обе оценки указывают одну недостающую роль и цитируют прямое свидетельство из уполномоченного документа. Содержательное встречное свидетельство о поступлении этой роли требует пересмотра. Заголовок и молчание источника не подтверждают непередачу | Можно выбрать утверждённый запрос после проверки применимости |
| Противоречие | У двух проверяющих совпали область вопроса, две разные исходные опоры и противопоставленные цитаты. Значения разных фасадов остаются раздельными. Равные одиночные линейные величины, например 2 мм и 0,002 м, исключаются из конфликтов | Можно выбрать уточнение с обеими цитатами |
| Требует сверки | Нет фактов, основание осталось простым упоминанием, исходники недоступны, не согласованы независимые оценки либо не установлен актуальный источник | Инженеру показана причина. Пункт письма не создаётся |

## Что меняет новое поступление

Проект хранит состав всех поступлений и историю оценок. Добавление материала заново определяет кандидатов для каждого вопроса. Ключ исполнения зависит от профиля вопроса, двух читателей и предъявленных доказательств. При неизменном составе доказательств переиспользуется результат сверки. Если два разных содержимых заявлены как версии одного документа без установленного приоритета, связанная область остаётся на проверке. Новизна даты поступления не определяет действующую редакцию.

Во время обработки досылки подтверждение старого среза как текущего закрыто. Новая оценка получает свой идентификатор. Прежние решение и текст сохраняются в истории. Повтор загрузки тех же байтов с теми же исходами идемпотентен. При неизвестном исходе вызова остаётся запись отправки. Дальнейшая попытка возможна после восстановления ответа либо подтверждения шлюзом, что вызов не состоялся.

## Граница реализации и проверка

В локальном harness профиль настраивается через `PackageReading`. При `upload` создаются `engineering/<revision>/assessment.json`, неизменяемые снимки и версия текущей оценки. Для каждой карточки `evidence` хранит кандидатов, `basis` — идентификаторы принятых оснований, `reviews` — исходные оценки. Поле `letter` содержит допустимые предложения. Вызов `confirm` по текущему идентификатору сохраняет отдельное решение и черновик с цитатами. При запуске без профиля продолжает работать исследовательский режим чтения с прежним интерфейсом. [Обычная загрузка](../experiments/package_review/package_reading.py) · [Отбор и проверка доказательств](../experiments/package_review/engineering_questions.py) · [Состояние проекта](../experiments/package_review/question_project.py)

Для квалификации используется синтетический пакет с фасадами А и Б. Два источника А называют один параметр по-разному. В требованиях нужная строка выбирается по области и роли вне словаря вопроса. На том же листе требований находятся исполнения 01 и 02. Контекстный отбор предъявляет обе строки, в принятые основания для AL-01 входит только исполнение 01. Контроль с единственной строкой 02 оставляет толщину AL-01 на внутренней сверке. Марка AL-01 повторяется на Б. Исходная комплектация А содержит прямую запись о предстоящей передаче узлов. Отдельная досылка содержит только сами узлы А. Оцениваются состав и происхождение карточек, выбор инженера, текст обоих писем, число повторных сверок и сохранение предыдущего решения. Команда из корня проекта принимает новый каталог для вывода.

```sh
python3 -m experiments.package_review.two_facades /путь/к/новому/каталогу
```

В первой поставке сценарий дал два внешних пункта по А — запрос узлов и уточнение толщины 2 мм / 0,003 м. После поступления узлов остался только вопрос о толщине. Две обязанности Б покрыты в обоих срезах. Сценарий использует локальные скриптовые адаптеры и синтетического инженера. Встроенный отбор по контексту расширяет материал для рецензентов и сам по себе не устанавливает семантическую эквивалентность. В текущем прототипе область задаётся для оригинала целиком. Материалы смешанной или неизвестной принадлежности требуют подтверждённого разделения до инженерного решения. Внешний индекс в сценарии не требуется. На целевом стеке отдельно проверяются качество поиска и интерпретации незнакомых формулировок, независимость вызовов моделей, адресное повторное открытие страниц и авторизованное подтверждение инженером.
