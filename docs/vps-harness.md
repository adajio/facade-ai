# VPS-harness Facade AI · контракт исполнения 0.7

**Назначение.** Исполнить на Linux/VPS без Codex весь цикл: найти оригиналы, самостоятельно выбрать чтение/новый участок, получить текст и пиксели, сохранить находки, провести независимые A/B и обсуждение, передать обоснованную матрицу инженеру. Harness — прикладной код worker, зарегистрированные инструменты reader и адаптер модельного протокола. Модель не получает shell, произвольные скрипты, общий диск, прямой SQL или неограниченную сеть.

Документ уточняет [техническую спецификацию](technical.md) и [агентный процесс](agent-workflow.md), не меняя владельцев данных. PostgreSQL владеет очередью и квитанциями, закрытое хранилище — оригиналами и производными, модель — выбором предметного действия внутри допуска, инженер — заключением и подтверждением оснований внешнего письма. Mastra исполняет зарегистрированный цикл; критические записи не зависят от lifecycle callback или единственного snapshot SDK. Здесь описан реализуемый контракт будущего продукта; запуск VPS и платной модели при его подготовке не проводился.

Для первого измерения конкретная пара, API и обязательная проверка адаптеров приведены в [профиле первого прогона](first-vps-run.md).

## Поставка и закреплённый профиль

Один релиз содержит API, worker/harness, версии схем и каталога, реестр инструментов, системные поручения, адаптер модели и манифест reader-образов. Изолированные Linux-reader имеют закреплённые версии исполняемых утилит, шрифтов, языковых данных OCR и параметров конвертации. Возможности PDF/DWG/DOC(X) квалифицируются отдельно на реальных байтах. Наличие CLI или расширения файла не является подтверждением поддержки формата.

`HarnessProfileRevision` фиксирует:

- Эффективные модели A/B и доступные версии, провайдеры/маршруты, настройки вывода и рассуждения, допустимые модальности, контекст и лимиты изображений. Разные алиасы одной модели не дают независимую пару; неизвестная внутренняя версия честно ограничивает воспроизводимость.
- Реестр tool names и версии аргументов/ответов; поддержанные режимы reader, правила масштаба и геометрии; политику сокращения контекста с сохранением ограничений и адресов.
- Разрешённые проекты/срезы и данные для провайдера, сетевой шлюз, максимальные ходы/инструменты/размеры, таймауты и денежный допуск. Для параллельных A/B — минимум две разрешённые сетевые позиции и независимую ёмкость исполнения.
- Профиль независимого чтения, раскрытия A/B и обсуждения, конечную политику исправления ответа, условия повторного применения сохранённых результатов.

Смена модели, разрешения изображений, адаптера сериализации, reader или значимой настройки создаёт новую редакцию профиля. Недоступная модель не заменяется другой через скрытый fallback. `text_only` допустим в квалифицированной текстовой задаче; он не выполняет визуальную часть сложного PDF/CAD. Новые расходы и доступ не разрешаются самим инструментальным намерением.

## Общая форма инструмента

Проект, пользователь, сессия, ветвь, входной срез, права, fencing token и лимиты **передаются harness вне аргументов модели**. Модель выбирает только операцию и предметные параметры. Выданные `sourceRef`, `unitRef`, `locatorRef`, `viewRef`, `objectRef` — непрозрачные ссылки, разрешаемые приложением в текущем доступном срезе. Ссылка не является правом доступа. Модель не назначает канонические ID источника, кандидата, области или ревизии.

```ts
type ToolRequest = {
  name: RegisteredToolName;
  arguments: unknown; // отдельная runtime-схема выбранной операции
};

type ToolResult<T> = {
  toolCallId: string;        // сервер связывает с фактическим ответом модели
  status: "ok" | "partial" | "pending" | "error";
  inputSnapshotId: string;
  data?: T;
  artifacts: ArtifactRef[]; // ссылка + тип; сама ссылка не означает доставку пикселей
  limitations: LimitationRef[];
  error?: { code: string; retryClass: "local" | "new_action" | "held" };
  nextCursor?: string;
  jobRef?: string;          // только pending; работу ожидает приложение
};
```

Успех с неполным диапазоном — `partial` с указанными обработанным и оставшимся объёмами. `ok` означает успешность конкретного инструмента, а не истинность предметного вывода. `pending` содержит идентичность reader-job; модель не должна оплачиваемыми ходами опрашивать её готовность. `error` имеет стабильный код, видимую причину и допустимые следующие действия. Неизвестный инструмент, неверный аргумент и неизвестная ссылка — адресный отказ; годные элементы той же выдачи не уничтожаются.

Пагинация использует `limit` от 1 до 100 (по умолчанию 50) и серверный `cursor`, закреплённый за срезом/запросом. Ответ различает `nextCursor`, завершённый перечень и неизвестный состав. Усечение контекста или лимит выборки никогда не превращается в «других объектов нет». Порядок и повтор страницы устойчивы в неизменном срезе.

## Как найти материал без известных ID и координат

Модель начинает с поручения, реестра инструментов и корневой навигации доступного среза. Ей не нужно угадать внутренний ID, страницу или рамку. `list_sources` возвращает источники; `inspect_source` — их структуру и доступные режимы; `list_units` — страницы, разделы, таблицы, изображения и CAD-пространства. Общий вид и `list_regions` дают адресуемые участки. Поиск помогает выбрать приоритет, но не заменяет обязательный обход оригинала, особенно при отсутствии текста в растровой вставке.

### Навигация и поиск

| Инструмент | Аргументы модели | Возвращаемые данные |
|---|---|---|
| `list_sources` | `{query?: string, kinds?: string[], cursor?: string, limit?: number}`; пустой фильтр перечисляет весь доступный срез | `items[{sourceRef,displayName,containerPath,actualFormat,revisionLabel,availability}]`, граница выборки и курсор. Имена помогают навигации, но не устанавливают предметную область |
| `inspect_source` | `{sourceRef}` | Хэш/редакция, sniffed format и расхождение с расширением, шифрование, контейнеры/вложения, доступные режимы, физическая структура либо причина неизвестности, список ограничений |
| `list_units` | `{sourceRef, kinds?: ("page"|"section"|"table"|"embedded_asset"|"cad_layout"|"cad_model"|"cad_layer"|"cad_reference")[], cursor?, limit?}` | `items[{unitRef,kind,label,parentRef,ordinal?,bounds?,available,capabilities}]`, полноценность перечисления. Физическая страница и печатный номер различимы |
| `search_text` | `{sourceRefs?: string[], query:string, match:"literal"|"terms", cursor?, limit?}` | Совпадения с `locatorRef`, контекстом, происхождением `native`/`ocr`, покрытием индекса и исключёнными источниками. Поиск не создаёт тихо новый OCR всего пакета и не доказывает отсутствие при нуле совпадений |
| `list_regions` | `{unitRef, basis:"grid"|"native_blocks"|"detected_regions", detail:"overview"|"readable", cursor?, limit?}` | `regionRef`, тип/метка, рамка и `viewRevisionId`, предусмотренный размер/масштаб. `grid` задаёт покрывающие лист участки по профилю независимо от найденных моделью таблиц; детектированные зоны не считаются исчерпывающей картой |

Архив и встроенный объект имеют строку происхождения, даже когда недоступны. Ленивая распаковка/перечисление возвращает `pending` или явное ограничение; источники дочерних объектов остаются производными закреплённых байтов родителя. Их появление в описи не означает новое незаметное поступление. Пароль, отсутствующий внешний файл и неизвестное содержимое контейнера не угадываются.

### Открытие, текст, таблицы и OCR

| Инструмент | Аргументы модели | Возвращаемые данные |
|---|---|---|
| `view_region` | `{unitRef, selector: Whole|Region|Rect|Object, detail:"overview"|"readable", includeNativeText?:boolean}`; `Whole={kind:"whole"}`, `Region={kind:"region",regionRef}`, `Rect={kind:"rect",viewRevisionId,rect:[x0,y0,x1,y1]}`, `Object={kind:"object",objectRef,context:"tight"|"surrounding"}` | Реальный `locatorRef`, `viewRef`, `viewRevisionId`, изображение/его artifact, размеры, поворот, трансформация, фактический охват, происхождение и ограничения. При недоступном рендере — отказ/частичный исход, не пустая картинка под видом успеха |
| `read_content` | `{targetRef, mode:"native_text"|"table", context:"local"|"with_headers"|"surrounding", cursor?, limit?}`; `targetRef` — выданные unit/region/locator/object | Текстовые блоки или ячейки с адресами и исходным написанием, заголовками/сносками, объединёнными ячейками и неполнотой. Не выдумывает строки из нарушенного порядка native text; сомнительная структура таблицы помечается |
| `run_ocr` | `{targetRef, languageHints?:string[], mode:"text"|"table"}` | Версия OCR, точное обработанное изображение, текст/слова и их рамки, исходная ориентация, доступная оценка распознавания и ограничения. Результат не заменяет оригинал и не получает предметный `supported` |
| `open_context` | `{locatorRef, direction:"around"|"previous"|"next", extent:"block"|"page"|"linked_source"}` | Разрешённый соседний контекст с новыми адресами, границей просмотра и фактической связью. `linked_source` возвращает обнаруженную ссылку/кандидатов разрешения; не открывает произвольный внешний URL |

Любое `view_region` с изображением добавляет **визуальный материал в подготовку следующего модельного входа**. ToolResult содержит ссылку для приложения; адаптер обязан отдельно поместить реальные поддержанные image parts в провайдерский запрос. Если API не принимает картинки в tool-result message, harness добавляет связанное мультимодальное сообщение в следующем допустимом месте протокола. Эта перестановка не теряет `toolCallId`, адрес и происхождение. Одной JSON-строки с `viewRef` или URL недостаточно.

`Rect` использует нормализованные координаты `[0,1]` в выданном прямоугольном виде: начало слева сверху, x вправо, y вниз, `x0<x1`, `y0<y1`. Все числа конечны. `viewRevisionId` обязателен, поэтому рамка старого повёрнутого изображения не интерпретируется в новом. Для листового вида область отображается в исходные координаты через сохранённую матрицу; рамка CAD-объекта преобразуется из системы объекта/пространства через закреплённый вид. Reader сохраняет фактический округлённый пиксельный охват. Выход за вид, устаревшая трансформация и неизвестная система координат дают адресный отказ, а не автоматическое исправление на похожую рамку.

Модель может выбрать `regionRef` из сетки без вычисления координат. Общий вид даёт пространственную ориентацию, а явное увеличение — читаемость. Вызов `run_ocr` без предварительного открытия изображения допускается технически, но он не является доказательством визуального чтения моделью. Изображение, OCR и нативный текст имеют отдельные записи предъявления.

## Особенности PDF, DOC(X) и DWG

### PDF

Физическая карта строится по оригиналу, включая пустые/смешанные/повёрнутые страницы и страницы с изображением без текста. Нативный слой, отдельно извлечённое встроенное изображение и растр всей страницы различаются. Полная страница сохраняет связь картинки с заголовком и областью; отдельная встроенная картинка может её потерять. Маска/clip, прозрачность, шрифт, поворот и raster/vector mix входят в квалификацию reader. Весь лист на уменьшенной картинке не засчитывается как чтение мелкого текста.

### DOC и DOCX

`inspect_source` определяет фактический формат, а не доверяет расширению. Для DOCX перечисляются документ, разделы/абзацы, таблицы с родителями, колонтитулы, сноски и вложенные изображения/объекты. У каждого есть стабильный структурный адрес в редакции и проверяемая связь с исходными байтами. Вложения не исчезают из-за того, что в основном тексте нет ключевого слова.

Для визуального просмотра reader создаёт закреплённое представление с манифестом конвертера/шрифтов. Страницы производного PDF — страницы этого представления, а не выдуманные стабильные страницы исходного DOCX. Если соответствие таблицы/абзаца визуальной странице приблизительно, точность маркируется. Для старого DOC конвертация выполняется в изолированном процессе без запуска макросов и сетевых обновлений; если точные нативные адреса недоступны, сохраняются оригинал, производное и предел привязки. Необходимое изображение или таблица открываются через те же `list_units`, `view_region`, `read_content` и `run_ocr`.

### DWG и CAD-пространства

В профиле DWG отдельно квалифицируются перечисление пространств/объектов, нативное чтение, рендер и геометрические измерения. Листовой просмотр не покрывает model space. `list_units` возвращает layout, модельное пространство, слои и внешние ссылки; начальный общий вид может быть недостаточен из-за удалённого объекта, огромных extents или скрытых слоёв. Эти условия показываются, а не превращаются в пустой успешный лист.

| Инструмент | Аргументы модели | Возвращаемые данные |
|---|---|---|
| `list_cad_entities` | `{sourceRef, spaceRef, entityTypes?:string[], layerRefs?:string[], text?:string, cursor?, limit?}` | Перечисляемые entity `objectRef`, исходный handle, тип, слой, имя/нативный текст, local/world bounds, transformRef, видимость и ограничения. Доступны TEXT/MTEXT, атрибуты, блоки, размеры и геометрия в пределах квалифицированного адаптера; вложенные блоки имеют путь экземпляра |
| `inspect_cad_reference` | `{referenceRef}` из `list_units` | Тип xref/подложки, сохранённый путь как метаданные, состояние `resolved`/`missing`/`unavailable`, версия и transform. Разрешение только в разрешённом наборе оригиналов; произвольный путь/URL не открывается |
| `measure_cad` | `{objectRef, measurement:"length"|"distance"|"area", secondObjectRef?:string, pointRefs?:string[]}` | Геометрический метод, выбранные примитивы/точки, система координат, значение, установленная единица либо `unit_unknown`, допуск/точность и ограничения. При неподдержанном примитиве — явный отказ, а не измерение его bounding box как истинной геометрии |

`pointRefs` выдаются инспекцией доступной геометрии, а не угадываются моделью. Если нужны такие точки, `list_cad_entities`/`read_content` возвращают адресуемые вершины или отдельный разрешённый курсор деталей объекта. Наличие объекта или текста не удостоверяет читаемость всех поддерживаемых типов DWG. Недостающие шрифты, proxy entities, отсутствующие xref и неизвестные единицы остаются ограничениями конкретного пространства/объекта.

Размерная надпись и вычисленная геометрия — разные основания. Надпись может быть переопределена; длина в model space при неизвестной единице не становится миллиметрами. Harness сохраняет `reported_annotation` и `measured_geometry` отдельно и не утверждает их равенство по форме текста. Ортографический рендер и визуальная линейка не заменяют точную CAD-геометрию. Изменение видимости/ракурса — производный вид, не правка оригинала.

## Нормализация и предметные выходы

| Инструмент | Аргументы модели | Ответ и граница |
|---|---|---|
| `normalize_quantity` | `{rawValue:string, rawUnit:string, localeHint?:string, quantityKind:string, targetUnit:string, evidenceRefs:string[]}` | Точное decimal-значение, исходная и целевая единица, преобразование либо причина неоднозначности. Локаль, разделитель тысяч/дроби и размерность не угадываются при неоднозначном источнике. Это вычисление над переданными значениями, а не подтверждение правильности исходного чтения |
| `publish_findings` | `{items: FindingDraft[]}`; каждый draft имеет локальный `clientKey`, kind, тезис, предмет, предложенную область, типизированное значение при наличии, evidenceRefs и ограничения | Отдельно для каждого `accepted` с канонической квитанцией, `retained_observation` либо `rejected` с причиной. Доверенные ID и версии назначает приложение. Исход одного элемента не откатывает соседние |
| `record_discussion` | `{discussionRef, items: DiscussionEntryDraft[]}`; элементы: `targetRef`, `kind:"question"|"objection"|"answer"|"review"`, содержание, открытые evidenceRefs, ссылки на прежние аргументы и verdict при review | Отдельные записи/вердикты по точным ревизиям. Контекст независимого чтения не может вызвать этот инструмент до разрешённого раскрытия. Пустое «согласен» и неоткрытое место не дают поддержанного основания |
| `request_research` | Адресное намерение по [ResearchIntent](../contracts/research-intent.v1.schema.json), без доверенных серверных полей и результата решения | Приложение дополняет каноническую запись, возвращает `accepted`/`reused`/`deferred`/`rejected`; действующие права и допуск не расширяются |
| `finish_pass` | `{requestedOutcome:"complete"|"partial"|"no_match", remainingRefs:string[], limitations:string[]}` | Квитанция запроса закрытия и фактический технический исход. Приложение сверяет неисполненные инструменты, карту диапазонов и обязательства. Модель не закрывает комплектность/ограничения собственным словом complete |

Инструменты публикации не являются обязательным шлюзом: типизированные элементы обычного ответа проходят тот же поэлементный приём после долговечного сохранения. Неоформленная заметка остаётся гипотезой; её нормализация из сохранённого материала требует проверки по оригиналу, а не подстановки угаданного факта.

Ведомость с общей суммой и ведомость с разбивкой не становятся конфликтом по одному несовпадающему числу. `read_content` сохраняет структуру строки/колонок, заголовки, подытоги, привязку к единицам и ограничения таблицы. Модель предлагает отношение `total/component`, состав суммирования и общую область как предметный тезис с основаниями. Код может точно пересчитать заданные значения; он не выбирает состав суммы и не объявляет эквивалентность документов без независимой проверки. Нормализованное значение всегда связано с исходным написанием/местом.

## Многоходовый автомат сессии

Состояние сессии и состояние внешней попытки — разные записи. Фактический модельный вызов не скрывается внутри одного «шага SDK». Реестр инструментов и допустимые исходы закреплены до вызова; адаптер сохраняет сырой доступный ответ до общей типовой валидации, чтобы один неверный элемент не уничтожил годные.

| Состояние | Вход и действие | Следующее состояние |
|---|---|---|
| `CREATED` | Прикладная транзакция создаёт назначение, привязку A/B, срез и профиль | `READY` |
| `READY` | Планировщик выдаёт аренду/fencing token, проверяет зависимости, доступную ёмкость и лимиты | `PREPARING`, `WAITING_RESOURCE`, `WAITING_DEPENDENCY` или `HELD` |
| `PREPARING` | Собрать собственный контекст, закреплённые tool results, текст/изображения; подготовить разрешённый запрос и его manifest | `DISPATCH_READY`; при недоступной модальности/артефакте `HELD` или адресная работа reader |
| `DISPATCH_READY` | Зарезервировать допуск, сохранить идентичность запроса и выполнить CAS права единственного отправителя | `WAITING_MODEL`; при доказанном отказе до отправки — возврат в `READY` по политике |
| `WAITING_MODEL` | Получить ответ и долговечно сохранить его вместе с известным расходом; потеря без долговечного ответа рассматривается отдельно | `INGESTING` либо `HELD_UNKNOWN` |
| `INGESTING` | По стабильным ключам принять типизированные элементы и зарегистрировать выбранные моделью tool calls. Каждая запись кандидата создаёт обязанность проверки | `EXECUTING_TOOLS`, `READY`, `SEALED` или `HELD` |
| `EXECUTING_TOOLS` | Валидировать и исполнить готовые независимые tool calls, сохранить отдельные результаты. Долгий reader-job выполняется отдельно | После всех необходимых результатов `READY`; при job — `WAITING_TOOL`; адресная ошибка возвращается модели следующим ходом в пределах политики |
| `WAITING_TOOL` | Reader-job завершился/отказал; приложение записывает результат без платного polling модели | `READY` или `HELD` |
| `WAITING_RESOURCE` / `WAITING_DEPENDENCY` | Событие освобождения ёмкости/появления входа; ожидание не держит worker | `READY`; исчерпанный допуск остаётся видимым удержанием |
| `HELD` / `HELD_UNKNOWN` | Сохранить причину, область влияния и условие возобновления; unknown сверяет операторский процесс | Возобновление только после допустимого события; независимые сессии продолжаются |
| `SEALED` | Сохранить неизменяемый снимок исходного прохода, включая partial/no_match и карту. Для A/B одного среза проверить готовность к раскрытию | Новая сессия `discuss_and_verify` либо ожидание второй ветви; сам SEALED не означает предметную полноту |
| `SUPERSEDED` / `CANCELLED` | Смена входного среза или явная отмена; сохранённые материалы и уже возможные внешние эффекты не уничтожаются | Новое адресное назначение при необходимости; неизвестные попытки остаются на сверке |

Переходы сопровождаются долговечной записью/событием в той же БД. Ответ, содержащий и готовые находки, и tool calls, сначала сохраняется; пригодные находки принимаются независимо от успеха следующих инструментов. Инструментальный ответ затем включается в следующий ход. Контекст сокращается только с сохранением адресов, исходных значений, текущих ограничений, незавершённых действий и ссылки на полную закрытую историю.

Инструменты из одного ответа могут исполняться параллельно, если их зависимости, права и квоты независимы. Если второй вызов ссылается на ещё не выданный результат первого, он не исполняется с выдуманной ссылкой: получает адресную диагностику и следующий ход. Порядок выдачи и причинные ссылки сохраняются. Большой размер tool result приводит к явной пагинации/ограничению, а не молчаливому обрезанию заголовка или единицы.

### Автомат внешней попытки и инструментальная квитанция

`ModelAttempt` проходит `reserved → dispatching → responded`, либо `dispatching → unknown`. Доказанный отказ до отправки допускает штатное продолжение того же разрешения. После `dispatching` истечение аренды не даёт права повторить запрос. Полученный ответ без долговечной копии остаётся неизвестным. Сверка различает восстановленный ответ, подтверждённый расход без ответа, доказанное отсутствие отправки и недостаток сведений. Новый workId, sessionId, провайдер или модель не обходят удержание той же операции.

Каждый `ToolExecution` связывает originating attempt/turn/toolCallId, имя и версию операции, hash канонических аргументов, branch/snapshot, предоставленные refs, reader-job и outcome. Читающий инструмент с теми же закреплёнными входами может переиспользовать сохранённый результат в пределах разрешений; ветви получают свои квитанции открытия. Кэш производных не раскрывает A результаты B. Мутации публикации идемпотентны по команде и отпечатку; изменённый payload под прежним ключом — конфликт.

Неразбираемый ответ сохраняется как технический исход. Успевшие до него отдельные законченные сообщения/кадры сохраняют результат, а произвольный префикс испорченного JSON не считается кандидатом. Разрешённый ход исправления формы имеет отдельный допуск и конечный предел; скрытого SDK retry нет. Данные, журнал, оригиналы, карты, кандидаты, вердикты и ручные решения переживают падение worker. После восстановления БД сетевой выход закрыт до сверки возможных более поздних отправок.

## Последний запрос инструмента, алфавит поля и расхождение изображений

Принятый запрос модели создаёт обязательство с ID вызова. Ограничение исследовательских ходов закрывает возможность начать новое исследование. По каждому уже принятому запросу reader возвращает изображение либо адресную причину отказа. Обработчик сохраняет все результаты и передаёт их в следующий запрос синтеза. При достигнутом лимите синтез выполняют с `tool_choice: none`. Состояние «результат подготовлен» отличают от «передан и получен ответ». Если даже синтез нельзя оплатить или его исход неизвестен, для инженера работа остаётся незавершённой. Неожиданные новые вызовы в синтезе получают отдельную запись. Для повторного запуска фиксируются сырой ответ, привязки к оригиналу/профилю, ID инструментов и содержимое результата. Известный ответ продолжают с последнего сохранённого состояния. Попытка без установленного исхода остаётся на сверке. [Исполняемый цикл испытания](../experiments/zoom/session.py)

Если после доставленных вырезок исследовательский вызов вернул известный `finish_reason=length` с пустым ответом и без запросов инструментов, допустим один новый синтез. Сырой оборванный ответ остаётся в журнале. Синтез получает прежний контекст, уже доставленные вырезки и нейтральную просьбу подвести итог. Новое исследование закрыто. Для локального опыта установлены 2400 выходных токенов на обычный ход и 4800 на этот восстановительный синтез. Это параметры опыта. Если синтез снова оборвался, итог остаётся незавершённым. Если доставка уже дала признак подмены, блокировка факта действует и при незавершённом итоге.

Правило алфавита относится к конкретному полю и версии инженерного каталога. Сохранить буквальную строку с её Unicode-символами. При наличии правила проверить точное соответствие и открыть источник значения. При неизвестном алфавите глиф, одинаково читаемый на кириллице и латинице, получает статус неоднозначного. Для синтетического поля без правила формата однозначно видимые цифры могут остаться непроверенными по формату с отдельной причиной. Удержание маркировки не закрывает подтверждённые зазор и единицу. Скрытая замена похожих букв и распространение правила ASCII на произвольные проектные обозначения недопустимы. [Прикладная проверка результата](../experiments/zoom/evidence.py)

Если байты выдаваемой области расходятся с эталонной отрисовкой закреплённого источника и преобразования, воркер удерживает вырезку до отправки. Если содержание открытого фрагмента противоречит метке или положению на обзоре, регистрируется локальное расхождение представлений независимо от технической целостности файла. Машинный ответ «отсутствует» по такому месту не применяется как пробел, не закрывает проверку листа и не порождает пункт письма. Для других обязанностей действуют их собственные опоры. В испытательном адаптере контроль испорченной доставки использует сохранённый оригинал, точный прямоугольник и сравнение SHA-256; намеренная передача чужой картинки допускается только в отдельном синтетическом поведенческом опыте. [Приёмка по трём границам](openrouter-zoom-test.md)

## Доказательство передачи изображения

Нужно различать четыре факта: изображение создано, адаптер включил его в провайдерский запрос, провайдер принял запрос и модель использовала визуальный материал для проверяемого ответа. Ни один последующий факт не выводится только из предыдущего.

[ModelInputReceipt](../contracts/model-input-receipt.v1.schema.json) создаётся **на границе окончательной сериализации запроса**, после изменений адаптера и до/при передаче шлюзу. Запись связана с `attemptId`, `workId`, `turnId`, `branchId`, `inputSnapshotId`, `modelRevisionId`. У части есть `contentPartIndex`; происхождение — `origin.kind=initial_overview` либо `tool_result` с `toolCallId`. Последнее различает первоначально поданный обзор и изображение по действию модели.

- `part.kind=inline_image`: SHA-256 фактических PNG/JPEG-байтов image part после снятия транспортного base64-кодирования, MIME, декодированные размеры; сравнение с разрешённым производным артефактом. Это hash переданного файла изображения, не строки пути и не исходной картинки до resize.
- `part.kind=provider_file`: неизменяемый file reference провайдера, идентичность загрузки и SHA-256 действительно загруженных байтов; ссылка в окончательном запросе должна относиться к этой загрузке и разрешённому артефакту. Один успешный upload без использования в запросе не доказывает предъявление.
- `part.kind=text_only`: явное отсутствие изображения. Текстовая ссылка на картинку не маскируется под image part и не засчитывается в визуальное чтение.

Для картинки сохраняются `parentRenderSha256`, `transformId`, `locatorId`, `viewRevisionId` и конечные размеры. Если адаптер ещё раз уменьшил/перекодировал изображение, manifest отражает именно получившийся вход, а transform сохраняет его связь с оригиналом. Неизвестное преобразование делает точность предъявленного места неподтверждённой. Размер multipart/base64 и ограничения провайдера проверяются до отправки; при блокировке до неё нет ложной квитанции egress.

Квитанция serializer доказывает представление, подготовленное/предъявленное адаптером, но сама не доказывает приём сети или восприятие моделью. Факт отправки/ответа подтверждает журнал ModelAttempt и доступная провайдерская квитанция. Даже HTTP-успех не удостоверяет прочтение мелкой таблицы. Для поведенческой проверки нужны слепые визуальные контроли и инженерный эталон.

Завершающий SDK/HTTP-адаптер обязан сохранять доступные поля и bytes для такой проверки. Если библиотека скрывает окончательный запрос, выбрасывает image part либо возвращает лишь общую ошибку без доступного тела, такой адаптер не квалифицирован для данного профиля до устранения ограничения. Внутреннее поле «image supplied=true» не заменяет сверку фактического DTO.

## Доказательство самостоятельного перехода

Самостоятельный переход установлен, когда сохранённый **сырой ответ модели** после предыдущего предъявления содержит вызов навигации/открытия нового участка, его аргументы разрешаются штатным инструментом, возвращённый материал действительно попадает в следующий модельный запрос, а результат продолжает предметный вопрос. Цепочка: `ModelInputReceipt₁ → raw model response/toolCall → ToolExecution → artifact/locator → ModelInputReceipt₂ → finding/limitation`.

Серверная операция покрытия всех тайлов полезна, но имеет происхождение `application_plan`, а не выдаётся за выбор модели. Готовый кроп, подложенный оператором, детерминированный scripted tool call и ответ MockTransport проверяют инфраструктуру; они не доказывают самостоятельную навигацию модели. Модель вправе выбрать выданный `regionRef`, координаты видимого листа, объект CAD либо соседний контекст; ей не требуется угадать скрытый ID.

Для будущего разрешённого испытания используются новые синтетические листы с изменяемым расположением малых областей и одноразовыми визуальными значениями. Эталон, координаты цели, OCR/нативная копия canary, текстовые имена с ответом и содержательные alt-описания не попадают во вход. В отдельном visual-only контроле профиль также запрещает получение canary через OCR/текстовые производные инструментов; в штатном испытании U OCR остаётся допустимым методом. Модель получает предметную задачу и обзор; делает собственный запрос участка; после увеличения читает единицу/контекст и сохраняет значение. Проверяются raw tool args, causal links, hashes фактических изображений и правильный адрес результата. Угадывание по заранее известному единственному примеру не засчитывается.

Отрицательные контроли:

1. Удалить image part при сохранённых текстовых дескрипторах. Транспортная проверка обязана заметить отсутствие; результат без новой картинки не подтверждает визуальный путь.
2. Подменить пиксели другим синтетическим значением при прежних внешних дескрипторах. В реальном поведенческом опыте ответ должен следовать действительным пикселям; в подставном транспорте проверяется только обнаружение изменённого hash/состава.
3. Перенести целевую область на другой участок нового листа. Зафиксированный заранее кроп перестаёт решать задачу; модель должна выбрать новый адрес по разрешённой навигации.
4. Уменьшить фактически переданные размеры ниже требуемой читаемости. Нельзя зачесть исходный high-resolution render, если в wire ушёл нечитаемый thumbnail.
5. Дать непригодное изображение/заголовок. Корректный исход — новое допустимое чтение либо явное ограничение; случайно верное число без единицы и основания не считается успехом.

Эти проверки подтверждают наблюдаемое использование визуального входа в заданном классе, а не дают математического доказательства внутреннего «восприятия» модели. Полнота и правильность сложного проекта отдельно проверяются по оригиналам.

## A/B, обсуждение и итог инженеру

Обе ветви исполняют один реестр возможностей над одинаковым закреплённым набором оригиналов с отдельно квалифицированными model profiles. Контекст каждой содержит только её исходные открытия и результаты. Ветви не получают карты/кропы/кандидаты друг друга, включая подсказки в tool acknowledgements, до фиксации независимых снимков одного среза.

Приложение создаёт новую `DiscussionRevision` после допустимого раскрытия: объединение находок, расхождения карт и незакрытые обязанности. Новые контексты A/B используют те же инструменты, заново открывают места, записывают возражение, ответ и отдельный вердикт. Обсуждение без реального открытия источника или голосование 2:0 не заменяет проверку. Новая материализованная находка из обсуждения имеет происхождение `targeted_followup`, исходный пропуск не стирается. Поздний первичный ответ независим только при доказанной изоляции его прежнего контекста.

Сырые исходы, нормализация, машинный вердикт и решение инженера — разные записи. Harness не имеет операции «подтвердить за инженера», «сменить каталог» или «отправить письмо». Приложение собирает согласованную матрицу; инженер подтверждает текущие строки/объём одним решением с основаниями и исключениями. Только подтверждённая обязательная нехватка или противоречие даёт пункт письма. Неизвестный provider attempt, отсутствие модели, плохой OCR и незавершённый CAD-reader остаются внутренними ограничениями.

## Изоляция, журнал и восстановление

Reader работает с отдельным каталогом задания, закрытой сетью и ограничениями CPU/RAM/диска/времени. Оригиналы доступны только на чтение. Конвертеры не выполняют макросы и внешние обновления; CAD-ссылки разрешаются только в принятом наборе. Путь внутри документа считается данными, не разрешением файлового доступа. Модели доступен только набор зарегистрированных операций текущего назначения; инструкции в документе не меняют полномочия.

Закрытый журнал хранит входной срез, release/profile revisions, задания/leases, обращения к reader, hashes оригиналов и производных, фактические model input receipts, ответы, поэлементный разбор, обсуждение и применённые решения. Содержательные payload и изображения находятся в защищённом хранилище по политике проекта. В экспортируемые технические логи идут allowlist метаданных, времена, размеры, типы действий, коды и непрозрачные ID; секреты, исходный текст и клиентские картинки туда не попадают. Учётные заголовки провайдера не сохраняются в payload для replay.

Один trace связывает выбор модели, её tool args, bytes предъявленного изображения, прочитанные места, выходной атом и строку матрицы. Причины очереди, платные отправки, reader CPU/IO и решение инженера измеряются отдельно. Повтор локального шага берёт прежнюю квитанцию; старая аренда не изменяет новое состояние. После смены редакции или существенного позднего основания пересматриваются только затронутые текущие строки, прежние выводы и отправленные тексты сохраняются исторически.

## Что выбрать и как квалифицировать

Первый VPS-срез должен включать весь описанный цикл на PDF с нативным и растровым содержимым, DOCX с таблицей/встроенным изображением и заявленной глубиной DWG, включая model space. Если CAD-конвертер/лицензия или DOC-reader отсутствует, поддержка не обещается; сохраняются оригинал, известная структура и явная граница. Это не заменяет требуемую квалификацию соответствующего формата.

| Уровень проверки | Что проверяется | Что этим не доказано |
|---|---|---|
| Локальный transport/geometry | Финальный сериализованный DTO, декодированные пиксели/размеры, трансформации, tool allowlist, поэлементный приём, replay и unknown на подставном транспорте | Чтение реальной моделью и самостоятельный выбор участка |
| R: одинаковые закреплённые места | Моделям поданы точно одинаковые разрешённые адреса/пиксели; измеряются число/единица/область и обсуждение | Самостоятельное обнаружение неизвестного места |
| U: штатная необогащённая загрузка | Новые оригиналы через обычный вход; нет скрытого готового кропа или подсказки. Проверяются поиск, переходы, pixels, A/B, матрица и инженерный результат | Перенос на неиспытанные форматы/масштабы и причинная польза только harness |
| Bridge при доступной сопоставимости | Новый контролируемый Codex-прогон и VPS-harness сравниваются на тех же закрытых пакетах с заранее подготовленным эталоном, одной подтверждённой эффективной моделью и сопоставимыми входами. Архивный пилот служит только регрессии | Если эффективная модель/предобработка нового сравнения неизвестна или несопоставима, причинная атрибуция невозможна; это не запрещает системную квалификацию U |

Исторические сохранённые случаи дают регрессионные сценарии: потерянная область, хороший элемент рядом с выдуманным ID, накопление без передачи, повторные чтения без вердикта, голодание очереди и неизвестная платная операция. В новый репозиторий переносятся механизмы отказа и синтетические контроли, а не клиентские данные. Для переноса нужны также закрытый эталон и несколько независимо подготовленных семейств пакетов, а не только один знакомый сложный лист.

До/после обсуждения показывает полезные и вредные переходы, но само не отделяет эффект диалога от дополнительного времени/чтения. Причинное утверждение о пользе обсуждения требует контроля с сопоставимым разрешённым дочитыванием на тех же замороженных A/B. Приоритет остаётся прежним: качество распознавания и заключения инженера, затем оптимизация расходов среди прошедших вариантов.

## Итог независимой проверки конструкции

Sol возразил против каталога, который умеет открыть только заранее известные лист/координаты: такая система пропустит MTEXT в model space, встроенную картинку и структуру сумм. В контракт включены discovery от описи, полный физический/структурный обход, CAD-пространства/объекты/xref, вложения DOC(X), самостоятельная навигация и сохранение структуры таблиц. Astra указал, что сравнительный bridge может быть технически недоступен из-за неизвестной эффективной модели/предобработки пилота. Принято: bridge необходим для причинной атрибуции, но не является обязательным условием качественного системного результата U.

Оба рецензента согласовали границу доказательства пикселей: manifest окончательного запроса удостоверяет представление адаптера; слепой поведенческий контроль и эталон отдельно проверяют использование/правильность. Ни доступный image ID, ни успешный рендер, ни подставной ответ модели не засчитываются как самостоятельное визуальное исследование. Реальная работоспособность этого harness ещё должна быть подтверждена разрешёнными испытаниями.

## Самостоятельное открытие DWG и доставка результата

Каждый из двух независимых читателей получает задание на пакет и отдельную физическую опись каждого DWG. Опись предоставляет пространства, типы и форму записей, распределение по объёму, пагинацию и адресное открытие. Читатель выбирает запрос, порядок и конкретный объект. Система записывает, что модель могла увидеть в каталоге, что запросила, какие части фактически принял провайдер и какой тезис модель связала с этой выдачей. Эти события имеют разные критерии проверки. После фиксации обеих ветвей другой читатель получает основание тезиса и сверяет значения, единицы и применимость. [Навигация в DWG](cad-discovery.md) · [Передача инженеру](engineer-fact-delivery.md)

В production Mastra исполняет шаг исследования и обращения к разрешённым инструментам. Адаптер провайдера владеет квитанцией передачи. Состояние наблюдений, проверок, инженерных решений и версия пакета принадлежат приложению. Экспорт читает один согласованный снимок этого реестра. Потеря текста модели при итоговом пересказе не может менять состав приложения к заключению.

На длинном чтении модель может потерять текст предыдущего открытия из рабочего контекста, хотя её запрос был доставлен. Испытательный цикл поддерживает повторный вызов `recall` по номеру квитанции своей ветви. Он возвращает сохранённые части с прежним точным адресом; повторная выдача имеет собственную квитанцию. Если визуальный адаптер при повторном рендере изменил байты, исходная выдача остаётся доступной. При повреждённом ответе цикл удерживает предыдущий материал на следующий ход. При `finish_reason=length` принимаются только синтаксически завершённые элементы массива наблюдений. Незаконченная строка, оборванная команда и новый запрос на самом последнем ходу остаются открытыми. Для ранее записанного опыта та же операция даёт отдельную производную карту с указанием восстановления. [Цикл исследования](../experiments/package_review/research.py) · [Разбор сохранённого ответа](../experiments/package_review/partial_response.py)

## Автоматическая передача на совместное чтение

Планировщик VPS подписывается на поступление оригиналов, связанные адресные наблюдения и новые доказательства. После рестарта он подбирает уже открытые проверки из хранилища. Читатель принимает два источника, может запрашивать другие области обоих и возвращает адресные данные независимо от полноты ответа соседней ветви. На границе сеанса сохраняются запрошенные открытия и их доставка. Для графического размера должны быть видны объект и оба конца соответствующей размерной линии. Обрезанная фигура требует расширения области вплоть до полного листа и последующего локального увеличения. Количество проверенных задач, неподтверждённые свойства и допуск письма видны отдельно. ## Общий денежный лимит пакета · 0.15

Перед выдачей платной сверки диспетчер проверяет состояние всей описи редакции. Пока чтение продолжается, приложение записывает её основания и версию. Шлюз проверяет остаток перед каждым внешним вызовом, включая дочтение и проверку текста вопроса. Восстановление по квитанциям и состояние очереди являются частью контракта VPS. Локальная реализация и квалификация порядка выдачи описаны в [правилах охвата](reading-coverage.md).
