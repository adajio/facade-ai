# Охват пакета при общем денежном лимите

Редакция 0.15 от 22 ноября 2026 года. Правило действует для обычной загрузки с двумя независимыми читателями. За распоряжение общим бюджетом отвечает harness. Модель выбирает, что прочитала и какую связь предлагает проверить. Регистрация этой связи сама по себе денег провайдера не расходует.

## Что считает инженер

Физическая единица — адресуемая страница, лист или область, которую reader включил в опись оригинала. Окно — диапазон материала внутри единицы, пригодный для передачи модели. Первичное задание связывает редакцию пакета, оригинал, единицу, окно и конкретную модель. У каждого оригинала видны число единиц в описи, число открытых, число полностью прочитанных и число с технически недоступными окнами. Охват показывают также по каждой модели. Для исходного плана сохраняются число заданий по состояниям и пропавшие адреса.

| Показатель | Когда засчитывается |
|---|---|
| Открыто | Хотя бы один читатель вернул результат по месту с привязанной квитанцией. Законченные строки оборванного ответа дают частичное открытие. Первая квитанция сохраняется и после неудачного повтора. |
| Полностью прочитано | Каждая назначенная модель завершила все окна единицы с принимаемым ответом. Для разделённого окна нужны результаты всех частей. Корректное чтение с нулём находок требует собственной квитанции и явного пустого результата. |
| Технически недоступно | Адаптер установил постоянный отказ по конкретной работе и дал диагностическое основание с квитанцией. Этот исход позволяет продолжать сверки по доступному материалу. Ограничение остаётся в заключении. |
| Ожидает | В очереди остались окна, продолжения, частичные ответы, неподтверждённые квитанции или разрыв описи. Исчерпание денег и временная недоступность относятся сюда. |

Полное чтение описывает исполнение плана. Правильность извлечённых полей и полноту описи reader оценивают отдельно по размеченному оригиналу, включая места без находок. Непредставленный оригинал виден с нулевым охватом. Если reader с первого раза пропустил отдельный фрагмент внутри представленного оригинала, одна очередь обнаружить его не может. [Приёмка распознавания](recognition-acceptance.md)

## Как расходуется общий бюджет

1. Зафиксировать исходную опись и задания обеих моделей. Выдавать по одному первому окну ещё не открытых единиц, чередуя оригиналы. Назначение первого читателя чередуется. Структурный ранг помогает выбрать окно внутри единицы. Крупный лист не получает все свои окна подряд.
2. Обойти остальные новые окна, затем завершить вторые независимые чтения и незакрытые попытки. Оборванный по длине диапазон из нескольких строк делится на меньшие части с собственными адресами. Сохранить уже принятые находки. Оборванная одиночная строка остаётся частичной до успешного чтения. Итоговые обязательства обеих моделей одинаковы.
3. При каждом принятом адресном наблюдении в одной транзакции сохранить факт, основания и текущую версию возникшей сверки. Это работает и тогда, когда чтение остального пакета продолжается. Ожидающая карточка показывает причину ожидания. Расходовать общий бюджет на первое обращение сверки, её продолжения и рецензию вопроса можно после завершения первичных работ по описи либо документированного постоянного отказа по конкретным работам. В момент перехода у обработчика нет первичных запросов в полёте.
4. После перехода двойная проверка использует доступный остаток. Если остатка нет, сохранить очередь. Новое поступление денег или восстановление после отказа продолжает ту же редакцию с первого незакрытого обязательства соответствующей фазы. Число появившихся сверок не ограничивает число чтений. Денежный предел проверяется шлюзом на каждой внешней отправке с учётом действующих резервов.
5. Инженер получает принятые адресные данные, состояние покрытия и сохранённые исходы выполненных проверок. При частичном охвате вывод по недочитанной области остаётся открытым. Пункт письма требует подтверждённого противоречия либо доказанной нехватки по применимому требованию. Ошибка reader, нехватка денег и ожидающая сверка сами по себе оснований для письма не дают.

Приоритет установлен для одного общего кошелька всего пакета. Он допускает ситуацию, в которой лимит полностью уйдёт на распознавание и платных сверок в этом запуске будет ноль. Фиксированные проценты расхода и предел числа заданий в этом правиле отсутствуют. Дополнительный бюджет не назначается автоматически.

## Состояние, восстановление и проверка

В локальном harness реестр SQLite хранит исходные обязательства, первые квитанции открытия, текущие состояния, чтения и версии сверок. Одновременные загрузки одной редакции используют общий реестр и одного активного исполнителя. Исчезнувшее из повторной описи окно остаётся открытым обязательством. Старое завершение без квитанции восстанавливают по сохранённому ответу шлюза. Неизвестный сетевой исход требует сверки оплаты. Инженерная сводка использует `coverage.json`, причины по окнам доступны в `source-work.json`, продолжения — в `source-subranges.json`. В VPS-профиле те же обязательства принадлежат приложению и его PostgreSQL. Mastra исполняет выданное модельное задание. [Планирование](../experiments/package_review/coverage_plan.py) · [Исполнение](../experiments/package_review/reading_flow.py) · [Журнал](../experiments/package_review/cross_read.py)

Приёмка включает обычную загрузку разреженных и плотных источников, конкурирующие сверки, отсутствие квитанции, частичную доставку, пропажу источника или окна, повтор после денежной отсрочки и продолжение оборванного диапазона. При любом остатке незакрытой первички число допущенных оплачиваемых сверок равно нулю. После закрытия последнего обязательства проверяют исполнение накопленных сверок. На живом пакете отдельно измеряют охват, качество фактов, пригодность заключения, текст письма и стоимость.
