Остальные требования v1.1, включая доступ, аудит, историю, сверку по двум оригиналам и профиль приложения В, применяются в полном объёме. ## 1. Поступление и применимость

- Пользователь с правом создания проекта может начать приём по названию проекта при нуле версий каталога, неизвестной стадии проектирования и без предварительной разметки фасадов или создания области. Право на первичное чтение определяется доступом к проекту и принятым материалам. Выявленная принадлежность к фасаду сама по себе доступа не даёт.
- Стадия рабочего процесса, стадия проекта и стадия конкретной редакции либо места в документе учитываются раздельно. Система показывает основание предложенной стадии. Титул отдельного документа не меняет стадию проекта. Изменение установленной стадии фиксируется на соответствующем объекте с основанием, версией и проверкой полномочий. Прежнее автоматически подставленное значение стадии само по себе доказательством не считается.
- До первой части сервер фиксирует объявленный состав и режим партии. Сервер завершает разовую декларацию после сверки состояния всех объявленных пунктов, включая явно разрешённые исключения с причиной. Для пополняемой партии требуется явное завершение. Передача, раскрытие состава и чтение имеют отдельные состояния. Принятые части, номера и причины ограничений восстанавливаются после разрыва, включая потерянный ответ о закрытии.
- При установленной применимости сервер может впервые закрепить единственную подходящую рабочую версию, утверждённую организацией. Отсутствие версии, пустая версия и неоднозначность профиля видны как отдельные причины ограничения оценки. Явное закрепление имеет приоритет, а уполномоченная смена сохраняет историю. Применимость пересчитывается по имеющимся доказательствам.

## 2. Первичные наблюдения и граница вывода

- После приёма оригинала система начинает самостоятельное чтение в рамках доступного ресурса. Наблюдения A/B публикуются по мере готовности без каталога и вопроса комплектности. Две ветви сохраняют раздельные контексты и опоры при запуске и продолжении. Наблюдение указывает редакцию, физическое место, доказанную или неизвестную роль источника и ограничение чтения. Применимое требование может использовать подходящее наблюдение, а роль места устанавливается по оригиналу.
- Система предлагает адресные связи с одним или несколькими фасадами. Общее назначение требует основания. Неоднозначная принадлежность, отсутствие установленного фасада в осмотренном месте и необследованный остаток показываются раздельно. В сводке рабочей матрицы применимое требование учитывается на каждый соответствующий фасад либо один раз на доказанный общий уровень. Опора одного фасада покрывает другой только при отдельно доказанной применимости.
- Полный пакетный вердикт требует независимо установленных границ по составу поступления, физическим местам оригиналов, охвату A/B и предметному перечню фасадов и общих требований. Список найденных фасадов и задания по опубликованной карте дают сведения о проверенной части. При неизвестной границе система показывает адресный результат в доказанном объёме и причину ограничения. Подтверждённый локальный конфликт по сопоставимым опорам из действующих оригиналов можно рассматривать до завершения общей описи по правилам v1.1.
- Для подтверждённой нехватки требуются применимое требование, проверенная граница и адресное свидетельство непередачи с проверкой альтернатив. Пустой поиск, устаревшее свидетельство, допустимый аналог, нечитаемость и незавершённая ветвь сами по себе не дают основания для внешнего пункта. Автоматический вывод, сохранённое заключение и явное решение инженера о начале работ имеют раздельные состояния.

## 3. Просмотр до находок

Разрешённый оригинал открывается из описи с момента подтверждения принятой версии, в том числе при нуле находок. У PDF доступны листание и скачивание исходной версии. Для смешанного пакета основание из вердикта открывается по адресу и версии в представлении соответствующего поддерживаемого формата. Если доступен только фрагмент, целая страница без точной рамки либо только оригинал, показываются фактическая точность и причина. На смешанном листе выдача оригинала, карты, OCR, превью и фрагментов проверяет действующий допуск. Карточка сохраняет ссылку на версию и показывает состояние чтения и доступное продолжение либо причину остановки. ## 4. Программа приёмки

| Проверка v1.1 | Дополнительный обязательный сценарий |
|---|---|
| AC01–AC02 · доступ и приём | Создать первый проект в организации с нулём версий каталога. Назначенный инженер загружает неизвестный пакет, продолжает с предпоследнего файла и видит окончательный результат после потери ответа о закрытии. Исходные ID и принятые части сохраняются. Отдельно проверить ограниченного читателя двухфасадного листа по прямым ссылкам и событиям. |
| AC03–AC04 · независимое чтение | До ручных правок подтвердить публикацию адресных наблюдений без вопросов, независимость входов A/B и их фактические маршруты. В смешанном PDF назначение каталога связывает требование с доказанным техническим местом. Совпадающее значение в коммерческом предложении не покрывает его. Первичное чтение повторно не запускается. |
| AC04 и AC06 · отрицательные выводы | Отдельно прогнать пропуск второго фасада картой и ноль находок обеих ветвей по его известному месту. В обоих случаях пакетный успех недоступен, проверенный результат по первому фасаду и ранний конфликт доступны. Проверить также пять отрицательных случаев из §2 после закрытия описи. |
| AC05–AC07 · рабочее место | Открыть разрешённый оригинал до находок, затем адресные опоры смешанного комплекта из вердикта. На смешанном исходе проверить сохранение заключения и решения о работах, автора и версии после reload, конфликт устаревшей вкладки и доступ читателя. Пройти письмо и затрагивающую досылку по v1.1. |
| AC08 и R04 · ресурсы и восстановление | На 4 vCPU / 16 ГиБ / 200 ГиБ проверить совместные очереди и резервы при одном тяжёлом локальном слоте, доступность малого проекта, восстановление при обрыве и отсутствие повторного списания при точном replay. |

Офлайн-испытания выполняются с нулём внешних списаний. Слепая оценка использует заранее закреплённый закрытый эталон по оригиналам, независимый от результатов карты и A/B. Фиксируются отдельно покрытие физической карты, охват ветвей, полнота предметного перечня и ложные внешние пункты. Допуск живого маршрута и его бюджета проверяется отдельно. Испытание с живыми пользователями проводится последним, после автоматизированной приёмки.
