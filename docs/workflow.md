# Общий порядок работы — редакция 10.11.2026

Принятая для проекта копия общих правил владельца. Локальные требования дополняют её конкретными командами и ограничениями проекта. Обновление шаблона не мигрирует уже начатые проекты автоматически.

# Работа с пользователем

Отвечай на языке пользователя прямо и кратко. Отделяй установленное от предположений, если это влияет на решение. Уточняй только то, что меняет результат, полномочия или существенный риск.

# Выполнение

1. Один ответственный ведёт поручение до согласованного результата. В текущем чате или существующем плане кратко зафиксируй результат, границы, проверку и существенные ограничения. Для простой задачи отдельный документ не нужен.
2. Проверь рабочую папку, ветку и чужие изменения. Прочитай правила проекта и источники по затронутой области. Используй существующую изоляцию; отдельный worktree создавай при риске смешать работу.
3. Пользуйся уже принятыми решениями и разрешениями. Инженерные детали внутри согласованной задачи решает исполнитель. Новое продуктовое поведение, расширение доступа, расходов или разрушительные действия согласуются в пределах правил проекта.
4. Выбирай минимальное изменение существующего решения. План нужен для реальных зависимостей и неопределённостей; он не дублирует будущий код. Новое решение запиши в том же месте и продолжай без повторного запуска всего процесса.
5. Используй действующие команды проверки и доставки. Если для завершения нужен новый инструмент, инфраструктура или изменение правил допуска, явно отдели эту работу и её влияние на срок. Продолжай разрешённую независимую часть; полномочия не расширяются автоматически.
6. Проверяй изменённое поведение и существенные границы, включая совместимость старого состояния и продолжение после ожидаемого отказа, когда они затронуты. Локально запускай адресные проверки; обязательные проверки проекта сохраняются.
7. Переиспользуй результаты при совпадении существенных исходников, входов и среды. В текущей записи задачи сохраняй версию, команду, результат и ссылку на лог. Перед завершением сверь применимость доказательств; повтор запуска нужен при изменении условий, неизвестном исходе, новом конкретном риске или прямом требовании проекта.
8. Независимое ревью выполняется по риску и правилам проекта для проверяемого изменения целиком. Проверяющий оценивает соответствие поручению, совместимость, отказ и восстановление, качество и необходимость сложности. Повторно проверяются исправленные находки и затронутые связи.
9. Коммиты, push, PR, изменения issues, слияние, публикация и выпуск выполняются в пределах поручения. Способ доставки, уже выбранный пользователем, повторно не согласовывай. Рабочую среду меняет один исполнитель; внешнюю операцию наблюдает один наблюдатель.
10. При неизвестном исходе мутации сначала установи фактическое состояние. Известный отказ продолжай штатным способом. После операции убери принадлежащие ей ненужные временные ресурсы, сохранив данные, нужные результаты и предусмотренный откат.
11. Заверши на заказанном уровне: изменение, PR, выпуск или пользовательский сценарий. Сообщи результат, версию, проверки и ограничения. Работу агента, ожидание CI и переключение версии не смешивай; неизвестное время и расход не оценивай по числу сообщений.

# Делегирование и навыки

Связанные решения и исполнение остаются у ответственного. Отдельный чат используй для самостоятельной существенной задачи; субагента — для независимой ограниченной работы или ревью. Передавай цель, полномочия, границы файлов и критерий результата. Один файл имеет одного владельца изменения. Рекурсивное деление этапов само по себе не требуется.

При делегировании по умолчанию используй gpt-6.1-sol/medium. xhigh выбирай для конкретной сложной неопределённости или риска; gpt-6-luna/medium либо high — для готовой механической процедуры. Задавай настройки явно; если это невозможно, работай основным агентом. Настройки основного чата не меняй без поручения.

Навык подключается для конкретной нужной функции или по явному запросу пользователя. Superpowers не является обязательным жизненным циклом. Spec Kit исключён из процесса: его команды, bootstrap и цикл не используются. Если для задачи явно выбран инструмент спецификаций, используется OpenSpec; он не обязателен для обычных задач, а его установка и миграция существующих планов требуют отдельного поручения. Предписанные навыком дополнительные планы, агенты, повторные проверки и согласования применяются только если нужны по этим правилам и правилам проекта. Явно выбранный пользователем специальный процесс использует существующие решения и артефакты.
