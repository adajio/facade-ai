# Предметные термины

| Термин | Значение для нового проекта |
|---|---|
| Проект | История по объекту, включая все поступления, области работ, запросы и письма |
| Поступление | Зафиксированная передача материалов. Одна досылка образует отдельное поступление в том же проекте |
| Оригинал и редакция | Неизменяемые байты и их привязка к полученному документу. Совпадение байтов допускает повторное использование чтения при сохранении истории обеих передач |
| Опись / паспорт поступления | Откуда пришёл каждый элемент, что принято, раскрыто, исключено, прочитано с ограничениями или осталось недоступным |
| Место | Проверяемый адрес в закреплённой редакции оригинала, включая страницу, лист, строку, объект или абзац в зависимости от формата |
| Позиция / часть | Требуемый элемент комплекта / отдельно проверяемая составляющая элемента. Позиция «Ведомость и установочные узлы СПК» содержит две части |
| Сведение | Параметр с исходным и нормализованным значением, единицей, областью и местами. Несколько значений могут относиться к разным вариантам |
| Область | Проект, вариант облицовки, элемент, участок, секция или фасад. Неустановленная область хранится явно |
| Кандидат | Машинный вывод, адресованный требованию или свободному наблюдению, области и версиям источников. Доступен для сверки |
| Вердикт проверки | Независимая оценка конкретного кандидата. Проверяющий может поддержать, отклонить или запросить уточнение. Инженерное подтверждение записывается отдельно |
| Покрытие | Вычисленный результат по части позиции, формату и области с учётом применимых оснований и ручных решений |
| Запрос / замечание | Адресная потребность в информации / результат проверки содержания. У каждого свои основание, история и правила закрытия |
| Запрос на уточнение по закрытой описи | Подтверждённая инженером просьба направить документ или указать нужное место. Основание содержит версии закрытых описей, проверенные места и учтённые альтернативы |
| Предпросмотр / черновик / отправленный снимок | Вычисленный состав, редактируемая сохранённая версия и неизменяемая фиксация фактически отправленного инженером текста |
| Попытка провайдера | Одна разрешённая внешняя операция с журналом отправки, исходом и учётом расхода. Неизвестный исход удерживает резерв |
| Объём письма | Явно выбранные проект, адресат, области и предметы проверки. Неразобранные вопросы вне объёма видны отдельно |
| Исход исследования | Результат конкретного задания по закреплённому входу. Частичное чтение, исчерпанный поиск, пустой ответ и потеря связи описывают работу системы |
| Доказанный пробел | Установлено, какая применимая часть ожидается, чем подтверждена непередача или полнота сверенной описи и почему другие текущие поступления её не закрывают |
| Пригодное письмо | На зафиксированном объёме все необходимые запросы вошли, лишних и неверно адресованных нет, основания открываются, редакция пригодна к внешней отправке по оценке инженера |
| Единица оригинала | Физическая страница, лист, диапазон строк, вид CAD либо учтённый контейнер. Существует независимо от находок |
| Обязанность проверки | Что требуется установить для применимого предмета и закреплённого набора входов. Видна до получения находок |
| Ограничение чтения или применения | Где материал недоступен, не проверен либо имеет неизвестную связь. Хранит причину, потенциальное влияние и основание разрешения |
| Запрос дополнительного исследования (ResearchIntent) | Зачем, какую единицу и каким методом требуется проверить. Запрос может предшествовать первой находке. Сохраняются решение, причина и связь с исполнением |
| Независимые читатели A и B | Два равноправных исследователя на разных моделях читают общий предмет до раскрытия чужих находок. После фиксации первичных версий могут выполнять взаимную проверку в новых контекстах |
| Сессия исследования и ход | Предметная работа по закреплённым входам и одно сохранённое действие в её составе. Число модельных отправок измеряется по журналу провайдера |
| Обзор листа (PageSurvey) | Карта осмотренных участков, замеченных зон и ограничений, привязанная к редакции физического листа и одному проходу |
| Процесс поступления (ReceiptProcess) | Долговечная прикладная запись, по которой видны ответственный инженер, исполнитель каждого перехода, ожидание, восстановление и открытые обязанности |
| Ревизия обсуждения (DiscussionRevision) | Зафиксированные исходные карты, объединённые находки, возражения, повторные открытия и предметные исходы по одному срезу |
| Оценка комплектности / заключение инженера | Машинный результат по обязанностям и самостоятельное решение человека по указанной версии состава, области и этапу. Заключение может стать основанием запроса |
| Предметный harness | Код внутри серверного обработчика, который собирает контекст конкретной ветви, исполняет действия модели через инструменты чтения и сохраняет результаты и незавершённую работу |
| Квитанция входа модели (ModelInputReceipt) | Запись о части фактически сериализованного запроса с привязкой к попытке, исходному месту и предъявленному материалу. Получение ответа и правильность прочтения проверяются отдельно |
