# Правила проекта

Шаблон v0.6, редакция 10.11.2026.

- На первом входе прочитай [общий порядок работы](docs/workflow.md) и [профиль проекта](docs/project-profile.md). При продолжении используй действующие решения и запись задачи; читай источники по затронутой области.
- При выборе архитектуры прочитай [архитектурные правила](docs/architecture.md). Rust — основной язык предметной логики; UI — Svelte + TypeScript, настольный профиль — Tauri. Создавай только нужные проекту части. Сохраняй явно выбранный пользователем стек и фиксируй существенные отступления.
- Spec Kit исключён. OpenSpec используется при явном выборе работы с инструментом спецификаций; его установка требует поручения. Superpowers и другие навыки подключаются по конкретной необходимости. Обязательной цепочки навыков, ролей и документов нет.
- Полномочия и заказанный результат определяет поручение пользователя. Шаблон не вводит этап «только документы» и не требует повторного разрешения на уже порученную реализацию.
- Способ проверки выбирай по задаче, риску и правилам проекта. Для воспроизводимой ошибки сначала зафиксируй отказ подходящей проверкой; для документации проверь содержание и ссылки. Не создавай тестовую инфраструктуру ради формального этапа. Ревью выбирай по риску и правилам проекта; сохраняй обязательные проверки после их определения.
- Проверяй совместимость, сохранение выполненной работы и продолжение после ожидаемого отказа, когда изменение затрагивает эти свойства. Различай локальный тест, CI, реальный запуск, выпуск и пользовательский результат.
- Команды сборки, форматирования, линтеров, тестов и доставки держи в конфигурации проекта; в профиле укажи путь к ним. Не добавляй инфраструктуру ради формального выполнения шаблона.
- Продуктовые решения принимает владелец; инженерные детали внутри согласованной задачи решает исполнитель. Термины предметной области фиксируй в GLOSSARY.md по мере появления.
- Секреты и реальные клиентские данные не включай в репозиторий, примеры и журналы. Используй синтетические фикстуры.

Источники продуктовых требований, предлагаемые границы Mastra и критерии инженерной приёмки перечислены в [карте спецификаций](README.md).
