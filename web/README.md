# Facade AI · веб-интерфейс v1.1

Svelte и TypeScript. Источник поведения — [приложение А](../docs/v1.1/interface.md) и [план v1.1](../docs/v1.1/implementation-plan.md) на срезе `42ed7fc`. Приложение открывается с того же origin, что API. Сборку `web/dist` обслуживает API. Переходы на проект, карточку, редакцию и основание представлены URL.

## Команды

```sh
npm --prefix web ci
npm --prefix web run check
npm --prefix web run build
```

Для разработки `FACADE_API_ORIGIN` задаёт адрес прокси Vite. Backend должен разрешать Origin браузера по правилам модуля access.

Проверки браузера используют действующий сервер и синтетическую организацию в отдельной БД. Задайте `FACADE_E2E_BASE_URL`, `FACADE_E2E_ADMIN_LOGIN` и `FACADE_E2E_ADMIN_PASSWORD` из окружения прогона. Для сценария с подтверждённым основанием дополнительно нужны `FACADE_E2E_BUILD_DIR` с абсолютным путём сборки и окружение той же выделенной БД и объектов. Нужны Chrome или Chromium. Для локального тестового TLS путь сертификата и способ доверия описаны в [инструкции стенда](../infra/test-stand/README.md).

```sh
npm --prefix web run test:stand
```

Тест [рабочего места](e2e/workspace.spec.ts) создаёт каталог, проект, область и назначения, прерывает ответы реального API на принятую часть и финализацию, проверяет ранний доступ к оригиналу, Range и отзыв роли. Дополнительный [сценарий](e2e/letter-versions.spec.ts) использует оригинал PDF и управляемые основания, сохранённые через reader и прикладную команду. Он проверяет клавиатуру, возврат фокуса, конфликт вкладок, выдачу текста и досылку. Стенд шага 7 запускает [свой сквозной тест](../test/e2e-supplements/README.md) независимо. В этих сценариях нет модельного транспорта и внешней отправки писем.

## HTTP и границы владения

| Раздел | Контракт |
| --- | --- |
| Сеансы, роли, проект, область и каталог | [access](../src/modules/access/README.md). `/api/me`, `/api/projects/:id` для доступа, CSRF, сильный If-Match и Idempotency-Key для команд. |
| Поступления, докачка и импорт | [intake](../src/modules/intake/README.md), [imports](../src/modules/imports/README.md). В реализации текущие маршруты этих модулей находятся под `/api`. Серверная карта частей определяет докачку после повторного выбора файла и проверки SHA-256. |
| Просмотр оригинала | [pdf](../src/modules/pdf/README.md). Карта единиц, цитата и представление под `/api/v1`, байты оригинала под `/api`. Размер изображения и преобразование сохранённой рамки поступают от reader. |
| Комплектность | [assessment](../src/modules/assessment/README.md). Текущая и историческая оценки, заключение и отдельное решение по позиции. Для подтверждения в письмо передаётся `requestExternal: true`. |
| Письма | [letters](../src/modules/letters/README.md). Актуальный текст и новый экспорт проверяют текущий допуск. Авторский текст сначала сохраняется как черновик. В форме сверки инженер выделяет область, предмет, действие, обозначения опор и значения с единицами в сохранённом тексте. Клиент передаёт UTF-16-границы, хэш редакции и текущие идентификаторы оснований, сервер проверяет совпадение. Снимок отправки и историческая выдача открываются по ID. Карточка показывает все различные адреса конфликта и дополняет отображаемые источники сохранённого письма опорами из его снимка оснований. |
| Досылка, срез и события | [supplements](../src/modules/supplements/README.md). GET `/api/projects/:id/snapshot` и пакетное дочитывание `/events?after=…`. Клиент дочитывает все страницы при `hasMore`, а при истечении курсора начинает с нового снимка. В поступлениях инженер уточняет области через `PATCH /supplements/holds/:id` и фиксирует влияние по версиям оценок через `POST /supplements/holds/:id/resolve`. Связь поступления с уже отправленным пунктом хранит `/supplements/links`. |
| Исследовательские вопросы | [questions](../src/modules/questions/README.md). Серверные кандидаты и пары читаются из карточек inquiry, в том числе при нуле результатов. Из карточки доступны замена выбранных адресов одного вопроса комплектности через `POST /api/v1/questions/:id/source-replacements` и история через `GET /api/v1/questions/:id/applicability`. В `If-Match` передаётся версия вопроса комплектности, а каждая опора закреплена тройкой `observationId, evidenceId, versionId`. Для подтверждения нужны опоры A и B, причина и явное согласие. Допустимые формы берутся из текущей оценки, включающей закреплённый каталог и применимые требования области. |
| Технический оператор | [gateway](../src/modules/gateway/README.md). Обезличенные данные `/api/operator/gateway/projects/:projectId`, адресная сверка `/attempts/:attemptId/reconcile`. |

Идентификаторы среза и условия фильтра идут в ссылке с обзора. Клиент скрывает защищённый экран при возврате из фона до перепроверки, обновляет право каждые 10 секунд и очищает данные после отзыва или истечения 30 секунд без подтверждения. Объектные URL представлений освобождаются при закрытии просмотрщика и при очистке сеанса.

## Совместный прогон

Сценарии web готовы для одного общего браузерного прогона со шагами 7 и 14. Для окна прогона нужны закреплённый манифест общей сборки с текущим `web/dist`, адрес, отдельная синтетическая БД и синтетический администратор. Локальный диагностический прогон использует собственную БД на внешнем SSD и вход через loopback. Сценарий шага 7 сохраняет своё доказательство отдельно.

## Открытые стыки

- Для проекций обзора нужны серверные агрегаты по подтверждённым байтам, открытым описям, уникальным физическим единицам A/B, сверкам и инженерным решениям. Нужны знаменатель, значение, фильтр и привязка к тому же срезу, который использует открываемый список. Текущий снимок supplements публикует версии, курсор и причины удержаний. Для показателей без источника UI показывает «—».
- Для карточки документа необходим защищённый снимок работы на версию оригинала и команды смены приоритета и адресного продолжения. UI подготовлен к работе с `GET /api/documents/:id/work?versionId=…`, `PATCH /priority` и `POST /resume`. Состояние должно содержать адрес продолжения, доступное действие, версию, причину и сохранённые наблюдения. Окончательный контракт уточняется по HTTP-модулю очереди и чтения. Карта физических единиц и неизменяемый оригинал используют действующий API.
- Для полного реестра «Сведения» нужен серверный список типизированных фактов с группировкой по предмету, области и варианту, стабильной пагинацией и командами подтверждения, правки, исключения и объединения. Пока экран показывает основания из исследовательских карточек и использует команду решения по inquiry.
- Для прогона штатной сборки требуется успешная регистрация модулей API и слот у владельца стенда шага 14. В локальной проверке собранный API запустился с миграциями отдельной БД на внешнем SSD.

### Адресная замена N06

В полной синтетической проверке допустимый PDF заменяет две выбранные опоры из разных прежних оригиналов только для одного вопроса. Ранее закреплённое решение по другой строке того же документа сохраняется. Для TXT, которого нет в закреплённом требовании, форма показывает причину удержания, сервер возвращает `422 support_format_not_admitted`. История доступна для чтения, подтверждение требует роли инженера. Отдельный сценарий открывает три разных оригинала в текущей и исторической карточках письма.
